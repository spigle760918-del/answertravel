# AnswerTravel V2 七天 Alpha 上线计划

状态：已确认并执行中  
目标日期：2026-09-19  
产品口径：单品牌、单模型、真实试运行版，不宣传为完整正式版

## 1. Alpha 必须实现

- 一个品牌空间和一个管理员；
- 品牌、别名、产品服务、差异化、竞品和禁用表达的基础真相资料；
- AI 根据文旅旅前阶段、人群、场景和决策疑虑拓展问题；
- 固定基准、探索和触发问题分组及版本；
- DeepSeek API 真实调用；
- 保存不可变原始回答、原始响应、模型、终端、时间、耗时、用量和错误；
- 计算有样本量依据的品牌/竞品提及率；
- 在可判断时记录出现顺序，在不可判断时显示“不适用”；
- 展示 AI 如何描述品牌，并下钻至回答原文；
- 只展示接口真实提供或回答中真实出现的 URL；没有引用时明确显示“该终端未提供引用”；
- 最小网页：品牌资料、问题组、采集任务、回答记录、基础洞察；
- 阿里云 HTTPS 部署、备份、日志、健康检查和最小告警；
- 所有测试数据与真实品牌数据隔离。

## 2. Alpha 明确不实现

- DeepSeek Web/App 搜索终端采样；
- 豆包、Kimi、元宝、千问等其他模型；
- 引用吸收和大规模信源正文研究；
- AI 自动文章发布；
- 小红书、网易、携程多账号发布；
- 本地采集/发布助手；
- 完整多租户商业化、SLA 或高可用集群；
- 没有实验依据的效果因果结论。

## 4. 阿里云部署基线

已知配置：Alibaba Cloud Linux 3、4 vCPU、8 GiB、100 GiB ESSD、3 Mbps，位于上海区域。该配置足够运行 Alpha 单机架构。

部署原则：

- Web/API、Worker、PostgreSQL、Redis和反向代理同机起步；
- PostgreSQL和Redis不得开放公网端口；
- 仅开放 SSH、HTTP和HTTPS所需端口，SSH限制来源并优先使用密钥；
- API Key仅通过服务器密钥/环境配置注入，不写入代码、日志或知识库；
- 原始证据、数据库和配置每日备份，后续接入阿里云 OSS；
- 3 Mbps足够文本 Alpha，图片和多账号发布阶段使用 OSS/CDN并重新评估带宽。

## 5. 关键风险

- DeepSeek普通 API 可能不提供联网搜索或结构化引用，不能代表 Web/App 搜索可见度；
- 七天内任何外部授权、DNS、服务器访问或依赖安装阻塞都会压缩业务功能时间；
- Alpha 只验证单品牌/单模型链路，不证明多模型和多账号稳定性；
- 所有未运行的测试必须标记为未验证，不得为赶日期改成“默认通过”。

## 6. 上线判定

只有以下条件同时满足才允许上线：

- 无模拟业务数据；
- DeepSeek 调用和原始回答真实；
- 品牌/竞品指标能够下钻；
- 不可变证据、租户隔离、幂等和错误路径测试通过；
- HTTPS、备份和基本恢复验证通过；
- 页面明确写明 Alpha、API 采样终端和能力限制；
- 没有阻断级安全问题。
