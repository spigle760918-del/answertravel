# 意图卡：恢复已确认产品界面与问题分析主链

状态：Gate A-E 已确认，Gate F 待封版

日期：2026-09-20

关联决策：`50-final-product-ui-and-implementation-adr.md`、`51-product-shell-readonly-evidence-intent-card.md`、`52-invite-auth-isolated-launch-intent-card.md`

## 1. 纠偏原因

邀请制身份与租户隔离实现时，新产品壳层错误地把已确认的信息架构缩减为“总览、游客问题、监测计划与运行、原始回答”四个入口，并把内部验收放入客户导航。该页面虽然保留了真实只读数据和身份隔离，但不再表达已确认的 AnswerTravel 产品主链，因此用户拒绝当前界面 Gate E。

本卡不扩大产品范围。它只恢复 ADR 50 已冻结的客户信息架构，并把身份系统重新放回产品外层。

## 2. 唯一业务主链

```text
监测品牌关心的游客问题
→ 查看多轮真实 AI 回答
→ 分析品牌、竞品、引用候选与来源快照
→ 区分观察事实、可能根因与证据不足
→ 决定内容、官网、信源、品牌事实、业务改进、补采或暂不行动
→ 按原问题与同口径条件复测
```

页面对用户的三段式表达固定为：

1. 监测问题；
2. 分析信源与竞对；
3. 决策优化方向。

“优化方向”不得被缩写成自动写文章。内容只是动作类型之一。

## 3. 原型到运行代码的映射

| 已确认原型元素 | 运行代码目标 | 真实数据源 | 无数据时 |
| --- | --- | --- | --- |
| 完整客户侧边导航 | `ProductShell` | ADR 50 固定结构 | 保留入口，显示能力状态 |
| 当前品牌空间 | 顶栏与账户区 | 服务端会话与 `workspace` | 不显示其他租户数据 |
| 三段式页签 | 游客提问分析页 | 页面级只读 API | 保持结构，显示证据不足 |
| 六列分析口径条 | 问题分析页顶部 | 问题组、计划、规则、目标上下文 | 未记录字段明确标为未记录 |
| 问题列表与轮次回答 | 监测问题 | `question_panels`、`observation_targets`、`observation_attempts`、`raw_answers` | 显示尚未采集或失败 |
| 品牌与竞品 | 分析信源与竞对 | `geo_entity_sets`、`geo_analysis_runs`、`geo_entity_mentions`、`geo_ranking_facts`、`geo_claim_facts` | 不生成演示比例 |
| 引用与来源 | 分析信源与竞对 | `citation_scans`、`citation_events`、`source_snapshots` | 区分未提供、链接候选、证据不足 |
| 根因与动作 | 决策优化方向 | `geo_diagnosis_snapshots`、`geo_action_proposals` | 不临时生成建议，显示尚无诊断 |
| 内部验收 | 不进入客户导航 | 独立管理员 API | 客户不可见 |

## 4. 本切片允许修改

- 恢复 ADR 50 的完整客户导航与 GEOFlow 对齐的紧凑布局；
- 新增“游客提问分析”页面级只读契约、租户隔离查询和界面；
- 已有总览、问题管理、计划、运行、原始回答继续使用真实数据；
- 尚未实现的确认栏目使用统一、诚实的能力状态页，并指明它在主链中的作用和所缺数据；
- 保留现有邀请、会话、成员关系、工作空间选择和退出逻辑；
- 增加契约、集成和界面验证。

## 5. 明确不做

- 不部署生产，不创建生产候选包；
- 不调用 DeepSeek，不创建付费采样或周期任务；
- 不增加 CMS、关键词库、标题库、图片库、站群分发、CRM 或流量归因；
- 不把北京珈程写入通用界面结构或规则；
- 不使用模拟竞品、模拟信源、模拟趋势或模拟效果填充页面；
- 不开放尚无后端命令和授权门禁的写操作。

## 6. 验收条件

1. 登录后首先看到完整产品结构，而不是工程验收或四页简化壳层；
2. 游客提问分析页能从问题下钻到真实回答，并在同页查看信源、竞争对手和动作依据；
3. 所有聚合结论显示样本量、规则版本和证据限制；
4. 无 GEO 分析、无引用、无第二平台或无诊断时不制造数据；
5. 两个租户 fixture 不串数据；
6. 桌面和移动视口无重叠、截断或不可操作区域；
7. 用户重新确认界面 Gate E 后，才允许制作独立上线候选。

## 7. 2026-09-21 实施进展

- 冻结导航字典已逐字落实：游客提问分析、游客问题管理、监测计划、周期监测、采集渠道、运行记录（含失败与费用）、AI 可见性、竞争对手分析、问题表现分析、AI 平台比较、引用与来源、历史变化、证据、决策与行动、复测和品牌真相。
- “监测计划”与“运行记录（含失败与费用）”已拆分为两个真实页面：前者显示问题组、渠道、样本和执行授权；后者显示成功、失败、预算停止、Token 用量和运行详情入口。
- 游客提问分析继续使用真实问题、回答、信源、实体和诊断数据；证据不足时不生成替代数据。
- “问题表现分析”已以每个游客提问为分析单位，显示计划样本、有效回答、失败样本、GEO 分析覆盖、品牌/竞对出现、引用候选与来源快照，并可下钻到该问题的回答与证据。
- 不计算脱离证据的“机会分”或综合指数；采集失败不计为品牌缺席，无排名证据时显示不适用。
- 移动端“问题表现分析”使用逐问题卡片，不要求用户横向滚动才能看到竞对与信源证据。
- 前后端类型检查、Web 构建、41 个测试文件共 177 项测试和本地恢复验证已通过；本轮仍未部署生产。
- 2026-09-21，用户在本地“问题表现分析”真实页面打开状态下回复 `yes`，确认恢复后的完整信息架构、游客提问主链、问题表现桌面表格与手机卡片 Gate E 通过。该确认不授权生产部署、模型调用、周期任务或客户官网修改。
