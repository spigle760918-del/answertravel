# 意图卡：游客提问中心的分析与信源证据 V1

状态：Gate A-F 已完成并封版

日期：2026-09-21

关联决策：`50-final-product-ui-and-implementation-adr.md`、`53-confirmed-product-ui-restoration-intent-card.md`

## 1. 用户结果

用户先选择品牌关心的某个游客提问，再看这个问题在真实 AI 回答中：

- 品牌是否自然出现，被如何描述，是否存在明确推荐或适用排名；
- 回答提到了哪些已确认竞争实体，但不在竞争范围契约完成前宣称市场胜负；
- 有哪些链接候选、平台结构化引用、页面快照和内容吸收候选；
- 哪些结论可以下钻到原始回答与来源证据，哪些只能显示证据不足或不适用。

## 2. 本切片实施页面

### 2.1 AI 可见性

- 以游客提问为主表，不先做一个脱离问题的品牌总分。
- 显示有效回答数、失败数、GEO 分析覆盖、品牌出现回答数、明确提及、主张数和适用排名。
- 失败样本不当作品牌缺席；没有列表或明确顺序时排名显示“不适用”。
- 可下钻到问题详情和原始回答。

### 2.2 引用与来源

- 以游客提问聚合链接候选、来源列表项、结构化引用、页面快照和抓取失败。
- 明确区分“回答中有链接”、“平台提供引用”、“页面抓取成功”和“内容可能被吸收”。
- 来源页必须显示状态、域名、快照时间和证据入口；失败或受阻记录不删除。
- 不把链接候选表述为“已被 AI 引用”。

### 2.3 竞争对手分析的边界

本切片不实施独立“竞争对手分析”聚合页。原因是当前数据库虽有 GEO 实体集和提及事实，但尚无 ADR 50 要求的版本化竞争范围契约。

当前只允许在游客提问详情中展示“这些已确认实体在几条有效回答中出现”。不生成竞品市场份额、综合分、胜负排名或自动竞对名单。

## 3. 真实数据与契约

- 输入：`question_panels`、`observation_targets`、`observation_attempts`、`raw_answers`、`geo_analysis_runs`、`geo_entity_mentions`、`geo_ranking_facts`、`geo_claim_facts`、`citation_scans`、`citation_events`、`source_snapshots`。
- 新增页面级只读 API，使用服务端会话解析租户；不接受客户端传入租户 ID。
- 每个聚合数必须可以回到回答 ID、采集上下文、分析规则版本和来源快照。
- 只读页面不创建问题、不发起采样、不重试失败、不抓取新页面。

## 4. 诚实状态

- 无已批准问题组：显示“尚无游客提问”。
- 有问题无回答：显示“尚未采集”。
- 有回答无 GEO 分析：显示“等待分析”。
- 有失败无回答：显示“采集失败”，不计入品牌缺席。
- 无引用候选：显示“当前回答未发现链接或来源项”。
- 有链接无页面快照：显示“来源尚未取证或受阻”。
- 只有单平台：保留 AI 平台比较的诚实能力状态，不用单平台数据伪造平台对比。

## 5. 明确不做

- 不部署生产，不制作服务器候选包。
- 不调用 DeepSeek 或任何付费模型，不新建周期任务。
- 不新增竞争实体、别名或竞争关系，不修改品牌真相。
- 不生成内容、任务书、官网修复、信源建设或发布动作。
- 不引入 CMS、关键词库、标题/图片库、CRM、流量归因或站群分发。

## 6. 验收条件

1. AI 可见性和引用来源均以游客提问为首要分析维度。
2. 所有计数和状态都可下钻至真实回答、分析与页面快照。
3. 失败样本、未分析回答、不适用排名和受阻来源分开显示。
4. 两个租户 fixture 无串数据，跨租户证据详情返回 404。
5. 桌面和手机界面都能从问题进入回答与来源，无页面级横向溢出。
6. 用户 Gate E 确认前，不进入生产候选。

## 7. 后续独立切片

竞争对手分析必须先实施版本化竞争范围契约，至少覆盖实体、别名、关系类型、重叠业务、区域、有效时间、证据/说明、确认人、状态和版本。该切片必须单独 Gate A，不在本卡内默认获得授权。
