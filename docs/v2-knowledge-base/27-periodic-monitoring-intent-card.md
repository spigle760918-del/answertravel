# 意图卡：北京珈程周期化监测、失败补采与自动复诊 V1

状态：Gate E 待用户验收
日期：2026-09-14

## 用户问题

首次真实基线通过后，如何在不要求文旅负责人每天操作的前提下，按固定口径自动重复采样、补采失败任务、比较变化并在真正需要决策时才请求 Yes/No？

## 推荐范围

- 固定使用已批准的 20 条问题，不静默改题；
- 默认每日创建一个 DeepSeek API 观察周期，每题 2 轮，单周期最多 40 个计划样本、60,000 tokens；
- 仅对可重试失败自动补采，终态失败如实保留，不通过追加无上限样本粉饰成功率；
- 每个周期自动完成不可变回答、引用扫描、基础 GEO 分析、与历史同口径比较和差距复诊；
- 只有数据完整性异常、预算/密钥问题、连续显著变化或需要高风险动作时提醒用户；普通成功周期无需人工介入。

## 输出

1. 持久化周期计划和执行状态，不依赖进程内定时器；
2. 同一问题、模型、终端、区域上下文、参数与轮次的可比较周期；
3. 成功率、Token、提及、排名适用性、主张情感、引用候选和诊断变化；
4. 失败补采与预算停止证据；
5. 验收台中的周期列表、变化说明和异常提示；
6. 可暂停、恢复且不会重复采样的幂等控制。

## 边界

- 仍只代表 DeepSeek API，不扩展到 Web/App 或其他模型；
- 不自动生成竞品直问，诊断建议深挖时另行请求一次 Yes/No；
- 不生成或发布优化内容，不修改官网和第三方账号；
- 不把单次波动描述为长期趋势或因果效果；
- 正式云端定时运行前，必须完成密钥轮换与安全托管，并保持阿里云现有业务隔离。

## 自动化等级

- 创建周期、执行、重试、证据保存、分析和普通报告：A0/A1，自动；
- 扩大模型、问题范围或预算：需新授权；
- 竞品直问、内容生成与对外发布：不在本切片。

## 验收标准

1. 人工触发一次测试周期后，系统可按相同契约生成后续周期；
2. 重复调度不会产生重复有效样本；
3. 失败、超时、预算停止和恢复路径均有自动测试；
4. 不可比较周期会明确拒绝拼接趋势；
5. 页面用业务语言说明“发生了什么、证据有多少、是否需要行动”；
6. 用户日常无需发送“继续”，只有真正门禁才需要 Yes/No。

## Gate A 请求

是否按以上边界进入“北京珈程周期化监测、失败补采与自动复诊 V1”？Gate A 的 Yes 授权实现和一次验收测试周期，不代表立即在云端开启长期每日计费任务。

## Gate A-D 实施结果

- 用户于 2026-09-14 明确确认进入本切片；新增持久化每日监测计划与不可变周期记录，固定使用已批准问题组版本、DeepSeek API、每题 2 轮、单周期最多 40 个样本和 60,000 tokens。
- 调度只负责产生观察计划，具体样本继续进入既有持久化队列；暂停状态不能产生周期，问题组版本或关键采样口径改变时会阻止静默拼接趋势。
- 真实验收执行“首次基线 + 1 个周期化验收周期”：共 80 个计划目标、78 条成功、2 条 `incomplete_response` 终态失败，总计 35,671 tokens；78 条成功回答全部完成引用扫描和基础 GEO 分析。
- 两个失败分别是“纯玩团/隐形购物”第 2 轮与“小众景点/文化街区”第 2 轮；失败未覆盖、未补写成功，也未追加超范围样本。
- 自动复诊统计 42 条中性有效回答，品牌自然提及 0，明确有序排名 0，引用候选 0；系统输出“当前没有达到需要内容或竞对深挖的可靠差距门槛”，竞对深挖保持 `no_trigger`。
- Node.js 24 本地 26 个测试文件、114/114 通过，PostgreSQL 冷备恢复、Redis AOF 恢复和 Web 生产构建通过；提交 `6038a64` 的 GitHub Linux CI `34854621551` 成功。
- 验收台接口与页面产物可用；专用浏览器自动化连接受当前 Codex 浏览器认证环境阻断，未把该工具故障冒充页面故障。用户可在已打开的 `http://127.0.0.1:4274/` 查看“可比较周期”和“采集运行”。
- 当前仅为本地验收中的一次周期，长期云端每日任务未开启；阿里云原生验证仍为 `blocked-by-host-policy`。
