# AnswerTravel V2 GEOFlow 对标产品界面重设计意图卡

状态：原功能一比一复刻方案已否决；按 AnswerTravel 核心闭环重新进入 Gate B 预览

日期：2026-09-17

## 1. 触发原因

当前 Web 是随工程切片累积的绿色验收台，把客户业务、生产门禁、CI、备份和告警混在同一产品外壳中。用户重新确认：GEOFlow 提供的不只是运营与发布流程参考，也是 AnswerTravel 前端用户体验、信息架构、视觉风格和布局标准。现状与该初衷背离。

## 2. 本轮目标

先完成一套直接来源于 GEOFlow 固定版本 UI V3 的可查看、可切换全局产品预览，让用户在任何运行代码变更前确认：

- 平台与单个客户/品牌空间的层级；
- 主导航、栏目名称与业务顺序；
- AI 工作台、数据、运营、内容资产、分发和系统设置的页面形态；
- GEO 指标、证据、诊断、行动、审批、发布和复测如何串成日常工作流；
- 客户工作台与内部工程验收/平台管理信息如何分离；
- 桌面后台的视觉语言、密度、状态和空状态。

## 3. 已确认的设计复刻基准

GEOFlow 固定版本：`abcc638887dd35f508a59815f01ed42bc4415a09`。

不再自行发明视觉风格。必须直接沿用 GEOFlow 的设计系统与成熟交互：

- GEOFlow 原始公共壳层、256px/72px 侧栏、64px 顶栏、账户区和用户入口；
- 白色/浅灰运营后台，蓝色主操作，克制装饰；
- AI 工作台是行动入口；
- 页面标题、短说明、右侧主操作；
- 数据只在有运营意义时形成指标摘要；
- 任务、筛选、表格、队列、审批状态和下一步清晰；
- 内容、数据、分发、系统配置边界明确；
- 原始设计变量、间距、圆角、表格密度、表单结构、状态、弹窗和响应式行为；
- 不使用营销式渐变 Hero，不以工程 Gate 作为客户主导航。

GEOFlow 的原始功能清单不再构成 AnswerTravel 的范围。具体产品边界以 `49-product-scope-convergence-adr.md` 为准。

## 4. AnswerTravel 业务接入规则

AnswerTravel 一级导航只围绕 AI 工作台、总览、观察、证据、诊断、决策与行动、复测、品牌真相组织。北京珈程只作为数据实例，不成为产品栏目。

## 5. 预览必须覆盖的主要页面母版

- GEOFlow AI 工作台；
- 数据中心及其页面内分析标签；
- 任务管理密集列表、创建/编辑和执行状态；
- 观察计划、运行与失败恢复；
- 原始回答、引用和来源证据下钻；
- 诊断、决策、行动审批与执行回执；
- 同口径复测和变化解释；
- 品牌真相与平台管理员入口；
- 登录、空数据、错误、无权限和移动端壳层状态。

## 6. 本轮非目标

- 不修改 `v2/web/src/App.tsx`、`styles.css` 或任何运行时代码；
- 不连接、不修改生产服务器或北京珈程官网；
- 不进行客户硬编码迁移；
- 不在未保留 AGPL 义务的闭源目录复制 GEOFlow 源码；
- 不把原型里的示例数值当成生产事实或写入数据库。

## 7. 门禁

- Gate A：用户已确认直接采用 GEOFlow 固定版本和 AGPL 路线；
- Gate B：依据原始源码完成全页面交互预览；
- Gate C：逐页检查平台/客户边界、事实等级和权限状态；
- Gate D：形成受控实施拆分、迁移和回滚计划；
- Gate E：用户明确确认最终原型；
- Gate F：Gate E 后才允许创建实施意图卡并修改产品代码。

## 8. 验收标准

- 首次进入即可看出这是多客户 GEO 运营平台，而不是北京珈程专用站或工程验收页；
- 主要工作能从 AI 工作台进入，并能沿观察、证据、诊断到行动和复测闭环；
- 日常客户用户不需要理解 CI、Docker、迁移、备份脚本或内部 Gate；
- 平台管理员仍有独立入口查看运行、审计和部署证据；
- 所有主页面在施工前均可被用户查看和确认。
