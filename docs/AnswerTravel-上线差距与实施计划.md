# AnswerTravel 上线差距与实施计划

更新时间：2026-09-09  
结论：当前版本已进入“本地单实例多用户试用版”阶段。真实认证、品牌权限、核心资源增量 API、本地 PostgreSQL 16、备份恢复和 DeepSeek 采集链路已经打通；正式上线仍需完成多租户/多实例验证、生产任务队列、真实发布渠道、邮件服务与部署运维。

## 1. 总体进度

| 阶段 | 当前状态 | 说明 |
| --- | --- | --- |
| PRD | 85% | 已明确文旅定位、核心流程、角色权限和上线验收标准 |
| 数据库设计 | 90% | 已有关系模型、四版迁移、JSON 导入、全部正常业务路径的资源增量写入、revision 并发保护和备份恢复实测；仍需多工作空间与多实例验证 |
| API 开发 | 92% | 已有版本化路径、真实认证、品牌级权限、CRUD、筛选、任务和完整回归；工作空间、渠道、核心业务、认证令牌和后台任务均已改为资源增量写入 |
| 前端界面 | 78% | 核心页面、登录注册、邀请分享和增量 API 已联动，成员改权与正式发布已有二次确认和重复提交保护；仍需拆分单文件并补齐全局错误、加载状态 |
| AI 任务接入 | 45% | DeepSeek 已真实调用并落回答、模型版本、耗时和评估结果；其余平台和生产队列待接入 |

## 2. 已经完成的部分

### 产品与交互

- 已从 Answerbit 方向调整为 AnswerTravel 文旅目的地问答。
- 已有设置向导、团队、品牌、竞品、监控问题、回答记录、洞察、素材、文章和任务页面。
- 首页设置向导未完成时才显示。
- 已支持列表、主题、平台视图，以及文章审核、发布、收录等演示状态。
- 已支持浏览器 localStorage 持久化，刷新后本地新增内容可保留。

### 本地业务 API

- [server/index.js](../server/index.js) 已提供团队、品牌、竞品、提问、素材、文章、回答记录、任务接口。
- 已有真实邮箱密码认证、access/refresh token、邀请注册和 JSON 原子写入。
- 权限同时按角色与品牌范围校验；品牌、提问、回答、素材、文章和任务均按 `brandId` 隔离。
- 管理员修改角色或品牌范围后，已有 access token 会在下一次请求立即使用新权限。
- 已有自动收录截止时间 `indexDueAt`。
- [server/test-api.js](../server/test-api.js) 已覆盖双品牌双账号隔离、邀请注册、动态改权、采集、筛选、发布、收录和快照脱敏。

### 前端 API bridge

- [api-client.js](../api-client.js) 已支持 Bearer 会话、断线回退、自动重试和增量资源读写。
- 整份 snapshot 写入仅保留为开发环境首次导入工具，生产环境已禁用。
- 邀请成员后会显示可复制的注册链接；受邀人打开链接即可进入预填邀请码的注册界面。

### 本轮上线骨架增量（2026-09-07）

- `server/config.js`：统一环境配置、来源白名单、访问令牌时长、演示认证开关和生产就绪条件。
- `server/security.js`：安全响应头、CORS 白名单、请求 ID 和登录限流。
- `server/db.js`：JSON/PostgreSQL 统一存储边界；PostgreSQL 写入已落到关系表事务。
- `server/migrations/001_initial.sql`：PostgreSQL 初始表、约束和索引。
- `server/openapi.yaml`：第一版 API 契约，支持 `/api/v1` 路径。
- 登录新增邮箱密码注册、短期 access token、refresh token 轮换、退出撤销和 `/auth/me`。
- 前端已提供邮箱密码登录、邀请注册、会话刷新和安全退出；仍需密码重置、邮箱验证与设备管理。
- PostgreSQL 驱动、迁移执行器和关系表事务存储已接入；多实例写入使用事务锁保护。
- 项目内嵌 PostgreSQL 16 已完成四版迁移、服务重启持久化、品牌隔离、备份校验和空库恢复验证，无需 Docker 或付费云数据库。
- 品牌、竞品、提问及其初始采集任务/回答记录已经改为按资源事务增量写入，不再因这些操作重建整个工作空间。
- 品牌、竞品和提问的创建、修改与删除已写入 PostgreSQL 审计日志，并提供团队管理员专用查询接口。
- 素材、文章、成员/邀请、刷新令牌和后台采集结果均已切换为按资源事务写入，工作空间快照只用于首次导入与备份恢复。
- 工作空间设置、团队资料和发布渠道也已切换为按资源事务写入，正常页面操作不再触发整份快照写入。
- 成员邀请/接受/改权、素材变更、文章编辑/审核/发布和任务操作已纳入管理员审计查询。
- 团队资料、设置向导和渠道配置已纳入审计；重复文章发布会复用执行中的任务，已发布文章会拒绝重复创建发布任务。
- 写接口增加字段白名单，禁止通过请求体覆盖资源 ID 或内部认证字段；生产环境禁用整份 snapshot 写入。
- PostgreSQL 关系表保存带 workspace revision 和事务锁；并发写入冲突返回 409，不静默覆盖。
- DeepSeek 已接入真实适配器，回答记录会保存模型版本、调用耗时、原始响应与评估结果。

## 3. 距离上线尚未完成的工作

### P0：不完成不能上线

1. **生产数据库**
   - 本地 PostgreSQL 实例、迁移脚本、约束、索引和备份恢复已经完成并通过验证；托管生产实例暂缓到本地测试收口后选择。
   - 将 workspace/brand 权限继续下沉到所有 PostgreSQL 写查询，并完成多实例并发验证。
   - `server/data.json` 已迁入本地数据库并生成带 SHA-256 校验的便携备份，可用于未来迁往托管 PostgreSQL。
   - 当前剩余：验证多工作空间隔离、多实例并发和生产队列。

2. **真实认证和权限**
   - 接入邀请邮件服务或企业身份提供商；当前为管理员手动复制邀请链接。
   - 增加密码重置、邮箱验证、登录设备管理和强制退出。
   - 在生产 PostgreSQL 环境继续验证跨工作空间隔离；当前实现聚焦单工作空间内多品牌。
   - 删除、改权和正式发布已增加二次确认与重复提交保护；核心业务与成员权限审计已完成。

3. **真实大模型任务**
   - DeepSeek 已接入；继续接入豆包、Kimi、元宝。
   - 任务队列、超时、重试、限流、成本记录和失败告警。
   - 原始回答、模型版本、引用来源和评估结果持久化。

4. **真实内容发布**
   - 官网、WordPress、微信公众号发布适配器。
   - 凭证加密存储，发布幂等，失败回滚和重试。
   - 收录检查接入实际搜索/站点接口，不能只用演示计时器。

5. **生产部署与安全**
   - 域名、HTTPS、反向代理、环境变量和密钥管理。
   - Docker 或托管运行环境、CI/CD、数据库迁移流程。
   - 日志、监控、错误告警、备份恢复和回滚。

### P1：上线前必须补齐

1. 将 36 万字节级别的单文件前端拆为路由、组件、状态和 API 模块。
2. 前端和后端正常业务路径均已使用资源增量 API；下一步拆分前端单文件并补齐统一错误与加载状态。
3. 所有页面补齐 loading、empty、error、forbidden、offline 状态。
4. 统一表单校验、字段错误、确认弹窗、重复点击保护和乐观更新回滚。
5. 完成移动端 375/390/768 宽度回归，键盘操作和无障碍检查。
6. 增加前端 E2E：首次设置、创建提问、回答筛选、文章审核发布、邀请注册。

### P2：上线后持续建设

1. 真实指标预聚合与长周期趋势查询。
2. 套餐额度、计费、用量告警。
3. 内容模板市场、自动建议和批量优化。
4. 更多模型平台与多语言、多地区监控。

## 4. 推荐上线路线

### Milestone A：生产骨架

- 固化 PRD、接口契约和数据库迁移。
- PostgreSQL + Redis/队列 + 对象存储。
- 认证、邀请、权限、审计日志。

### Milestone B：真实数据闭环

- 接入一个真实模型平台。
- 完成任务队列、回答记录、来源解析和概览指标。
- 完成一个真实发布渠道和收录检查。

### Milestone C：前端收口

- 页面拆分、增量 API、错误/加载/空状态。
- E2E、移动端、无障碍和权限回归。

### Milestone D：发布上线

- 生产部署、域名 HTTPS、监控、备份、告警、回滚。
- 小范围邀请真实用户试用，修复阻断问题后再扩大范围。

## 5. 当前不应对外承诺的内容

- 目前只能称为已接入 DeepSeek 单平台真实监控，不能称为多平台全面监控。
- 目前不能称为已实现真实搜索收录和发布。
- 目前不能称为已完成生产级多租户数据库、邮件邀请和账号安全体系。
- 当前更准确的对外说法是：**AnswerTravel 单实例多用户试用版，已打通 DeepSeek 数据闭环**。
