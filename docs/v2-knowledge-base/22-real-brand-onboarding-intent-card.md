# 意图卡：真实品牌资料接入与单品牌运行基线 V1

状态：Gate A-D 已完成，Gate E 待用户验收
日期：2026-09-14

## 为什么现在做

V2 的工程、证据、问题、采样、引用、GEO 情报、决策和可比较周期链路已经用隔离测试品牌验证，但这些结果不代表用户的真实品牌。上线 Alpha 前必须先把真实品牌资料变成经人工确认、可追溯、可公开范围明确的品牌事实版本，再由 AI 生成真实游客问题组。不得把验收品牌或模拟数据带入生产路径。

## 用户确认的问题

是否进入真实品牌资料接入：由用户提供现有品牌与竞品资料，AI 自动整理、拆分事实、发现冲突和缺口、生成最少追问；用户审核后形成首个真实品牌事实版本和真实问题组草案？

本 Gate A 仅授权资料处理和草案生成，不授权 DeepSeek 答案采样、不授权竞对直问、不授权内容发布或网站修改。

业务确认：2026-09-14，用户明确回复“YES，进入真实品牌资料接入”；随后确认本次 Alpha 主品牌为“北京珈程国际旅行社”。

当前资料边界：V1 历史文件仅提供候选别名“北京珈程”、候选官网 `http://www.jiacheng666.com` 和 5 条云南旅前问题，没有竞品、产品、服务、差异化、资质或公开边界。除用户明确确认的主品牌名称外，其余均不得作为已批准事实；V1 模拟指标、回答、趋势和发布数据不得导入。

## 本切片输入

- 品牌法定名、常用名、别名、所属企业和官方联系方式；
- 目的地、产品、服务、人群、价格/时效边界及适用与不适用场景；
- “人无我有、人有我优”的可验证颗粒度事实；
- 资质、保障、服务流程、真实案例或其他可核验来源；
- 官网及官方账号、允许公开内容、敏感内容、禁用表达；
- 主要竞品名称、别名和选择理由；
- 用户已有文档、表格、网页链接或结构化资料。

## 本切片输出

1. **资料接收清单**：记录文件/链接来源、时间、哈希和处理状态，不泄露密钥或个人敏感信息；
2. **品牌事实草案**：每条事实独立、标记 F0/F1、来源、公开范围、有效期和状态；
3. **冲突与缺口报告**：区分确定冲突、可能重复、证据不足和必须人工确认项；
4. **竞品实体集草案**：名称、别名和角色明确，不推断未提供的竞品能力；
5. **最少人工确认单**：只询问会改变公开事实、竞品范围或合规边界的问题；
6. **真实问题组草案**：基于已审核品牌事实，由 AI 按旅前阶段、人群和场景拓展并隔离中性/品牌/竞品/热点问题；
7. **运行准备状态**：明确资料是否足以进入真实答案采样 Gate A。

## 固定业务规则

- 原始资料与解析结果保留来源关系；AI 归纳只能是草案，不能自动成为企业真相。
- 资料相互冲突时不得自行选一个值；必须显示冲突和证据，由用户确认。
- 未证明的“最好、第一、零投诉、绝对保障”等表达不得进入已批准事实。
- 个人信息、合同金额、内部成本、账号密码和 API Key 默认不得进入公开品牌知识。
- 竞品只建立实体与监控范围，不在本切片评价优劣或采集“竞品怎么样”。
- 真实问题组生成可以调用 DeepSeek 进行草拟，但调用前需显示最小预计请求与 Token 上限；本意图卡不授权真实答案采样。
- 品牌事实和问题组必须分别人工一次 Yes/No 后才可批准；批量确认优先，不要求用户逐字段操作。
- 所有真实资料按租户隔离；公开仓库不提交真实私密资料、密钥或服务器凭据。

## AI 与人的分工

- AI 自动完成格式整理、事实拆分、来源关联、冲突/缺口检查、竞品实体规范化和问题拓展草案。
- 人负责提供资料，并对企业事实、公开范围、竞品集合和最终问题组做少量批量 Yes/No。
- 自治等级为 A1 建议与 A2 草拟；不进入 A3/A4 执行。

## 验收场景

1. 能接收用户已有资料并显示来源，不要求用户手工转成工程格式。
2. 同一事实存在冲突时显示冲突，不自动覆盖或选择。
3. 敏感信息默认不公开，API Key 永不进入事实库、日志、网页或 Git。
4. 品牌能力没有可核验证据时标记待确认，不生成营销主张。
5. 竞品实体与品牌实体分开，别名匹配不会跨品牌误归属。
6. AI 生成的问题覆盖核心旅前决策场景，并保持中性问题与品牌/竞品直问隔离。
7. 未获品牌事实 Yes 时不能批准事实版本；未获问题组 Yes 时不能进入真实答案采样。
8. 用户可在验收网页查看事实、冲突、缺口、竞品和问题组，不需要阅读代码或数据库。

## 非目标

- 不在本切片执行真实品牌答案采样或多模型监控；
- 不采集竞对直问、网站正文、平台评论或热点；
- 不生成或发布优化文章，不修改官网或第三方账号；
- 不把现有隔离测试品牌的任何指标迁移为真实品牌指标；
- 不要求用户提供账号密码、验证码或把 API Key写入资料。

## Gate A 通过后的实施顺序

1. 固定真实资料接收、解析、来源和敏感信息边界契约；
2. 用户提供现有资料，AI 自动形成事实与竞品草案；
3. 自动运行冲突、缺口、重复和公开范围检查；
4. 向用户展示最少批量确认单，批准真实品牌事实版本；
5. AI 生成并展示真实游客问题组草案，用户一次 Yes/No；
6. 完成测试、浏览器验收与 Gate E；
7. Gate F 封版后，另行建立真实答案采样意图卡和费用授权。
