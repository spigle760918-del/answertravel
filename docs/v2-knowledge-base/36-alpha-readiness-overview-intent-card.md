# 意图卡：单品牌 DeepSeek Alpha 上线就绪总览 V1

状态：Gate A-D 已完成，Gate E 待用户验收
日期：2026-09-15

## 目标

把已封版模块、真实运行证据、上线前置条件和明确阻塞集中成一页可读总览，帮助业务负责人判断“能否进入单品牌真实试运行”，而不是继续按业务细节拆分 Gate。

## 自动汇总范围

- 已封版的品牌真相、问题组、DeepSeek API 采样、引用/信源、GEO 情报、诊断、监测、事实补充工作台；
- 本地测试、数据库/队列恢复、Web 构建和 GitHub Linux CI 证据；
- 阿里云部署、HTTPS、备份、日志、告警和域名等上线前置项；
- Alpha 明确不包含的多模型、多账号发布、Web/App 搜索终端和自动对外发布。

## 不可伪造的状态

- `ready`：有当前版本的可追溯证据；
- `pending`：尚未执行或尚未取得材料；
- `blocked`：受外部环境或主机策略阻断；
- `not_in_alpha`：明确不属于本次 Alpha。

总览不得将 `pending` 或 `blocked` 汇总成“已上线”，也不得把 DeepSeek API 结果描述为 Web/App 搜索表现。

## 下一步自动动作

1. 从知识库和当前验收接口生成状态矩阵；
2. 对每个 `pending/blocked` 项给出最小解决路径和是否需要用户确认；
3. 仅在所有上线硬门槛满足后建议进入云端预发布；
4. 继续保留阿里云 `blocked-by-host-policy`，不要求用户重复执行技术命令。

## 非目标

- 不新增业务事实；
- 不自动修改阿里云现有业务；
- 不开放正式发布权限；
- 不把 Alpha 变成完整商业化版本。

## Gate B-D 实施证据

- 验收接口新增 `alpha-readiness.v1` 状态矩阵，逐项区分 `ready/pending/blocked/not_in_alpha`。
- 当前矩阵包含14项：核心产品与工程能力按真实数据库和固定 CI 证据判定；阿里云原生验证保持 `blocked-by-host-policy`；公网 HTTPS、云端备份恢复、云端日志告警保持待完成；多模型、多账号发布和 Web/App 搜索终端明确不属于本次 Alpha。
- 总体状态由“上线硬门槛”自动汇总；存在阻塞时不得显示为可上线。
- 验收台项目概览新增四类数量、总体结论和逐项证据说明。
- Node.js 24 下33个测试文件、140/140通过；PostgreSQL冷备恢复、Redis AOF恢复和Web生产构建通过。
- 初次实现提交 `89a6aea` 的 GitHub Linux CI `34944606535` 成功；随后增加旧验收进程兼容渲染，确保当前页面刷新时不会因后端进程尚未重启而空白。
