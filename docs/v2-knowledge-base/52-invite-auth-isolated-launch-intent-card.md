## 1. 用户结果

受邀的文旅品牌成员可以在受保护入口登录，只看到自己被授权的品牌空间；拥有多个品牌空间时必须明确选择，单一成员可直接进入。登录后继续使用已验收的只读产品壳层，退出或会话失效后不能继续读取任何客户 API。

本切片同时形成可回滚的隔离部署候选，但不直接替换当前公网入口。

## 2. 推荐身份方案

- 邀请制邮箱与密码登录，无公开注册。
- 密码只保存现代自适应哈希，不保存或记录明文；首次凭据通过独立安全渠道交付。
- 服务端随机会话，浏览器只持有 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- 会话关联用户、租户成员关系、角色、创建时间、最近使用和失效时间；退出、禁用成员或管理员撤销后立即失效。
- API 只从已验证会话解析当前租户，删除公开入口对 `PRODUCT_TENANT_ID` 的依赖。
- 一个用户可以属于多个租户；只有一个成员关系时直接进入，多个时进入品牌空间选择页。
- 第一版角色仅 `owner` 与 `viewer`。本切片页面均为只读，两者都不能执行监测、修改问题或发布。
- 因生产邮件通道尚未验收，不采用邮件验证码、魔法链接或自助找回密码；忘记密码由平台管理员受审计地重置，后续邮件通道另立切片。

## 3. 必须先看到的界面

施工顺序固定为：登录页、品牌空间选择、会话失效、无权限，然后才接入真实身份后端。所有页面沿用已确认的 GEOFlow 设计系统，不新增营销首页。

每完成一个可交互页面，保持本地预览可访问并请求用户核对文字、结构和操作；不能等到生产部署后才展示。

## 4. 数据与 API

预计新增版本化数据：

- `users`：账号状态和密码哈希；
- `tenant_memberships`：用户、租户、角色和状态；
- `user_sessions`：不可逆令牌摘要、有效期、撤销时间和审计字段；
- 登录失败与会话事件进入审计，不记录密码、Cookie 或完整令牌。

预计新增接口：

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `GET /api/v1/auth/session`
- `GET /api/v1/workspaces`
- `POST /api/v1/workspaces/:tenantId/select`

现有 `/api/v1/workspace` 与全部产品读取接口改为从会话上下文读取租户。路径、查询参数、Header 和浏览器存储仍不能直接指定任意租户。

## 5. 安全门禁

- 登录接口限速并使用恒定失败文案，不能枚举邮箱是否存在。
- 所有变更状态接口校验同源、Origin 与 CSRF；登录后旋转会话标识。
- Cookie 仅 HTTPS 发送；Nginx 与应用明确可信代理边界。
- 数据库继续使用非超级运行账号和 RLS；成员关系校验先于租户事务。
- 未登录 API 返回 401；已登录但无成员关系返回 403；跨租户资源仍返回 404。
- 页面缓存和 API 响应禁止被共享缓存；退出或切换品牌先清除当前页面数据。
- 不在 URL、日志、HTML 或前端构建中放置密码、会话令牌、数据库地址或 API Key。

## 6. 隔离上线步骤

1. 本地完成四类身份界面并由用户确认。
2. 完成身份契约、迁移、服务端会话和双租户安全测试。
3. 在隔离环境使用测试账号验收登录、切换、退出、过期、撤销和跨租户阻断。
4. 生成带版本、构建哈希、许可证和对应源码说明的部署候选。
5. 对现有生产数据库先备份并做迁移预演；任何历史迁移哈希异常立即停止。
6. 新候选只在受保护的隔离入口或独立路径验证，不覆盖当前公网服务。
7. 用户实际查看公网候选并通过 Gate E 后，另行请求正式流量切换授权。

## 7. 自动化验收

- 正确登录、统一错误登录、限速、退出、过期和撤销；
- 单租户直达、多租户选择、无成员关系阻断；
- 伪造 tenantId、Cookie、Header 和跨租户资源访问失败；
- CSRF、Cookie 属性、缓存头、安全响应头与日志脱敏；
- 两个品牌使用同一套页面/API，且不会闪现或缓存上一品牌数据；
- 桌面与手机登录流程、键盘焦点、错误文案、深链接回跳和无障碍；
- 迁移、备份恢复、候选回滚及旧只读入口兼容。

## 8. 明确非目标

- 不开放自助注册、公开试用、短信登录、社交登录或邮件魔法链接；
- 不实现计费、订阅、席位购买或复杂 RBAC；
- 不开放任何问题、监测、诊断、决策、发布写操作；
- 不调用 DeepSeek，不创建周期任务，不修改客户官网；
- 不因本切片通过而自动切换 `geo.21y.com` 公网流量。

## 9. 回滚

- 身份数据采用新增迁移，不改写既有业务证据；候选失败时关闭新入口并切回上一静态/API 镜像。
- 数据迁移前保留可恢复备份；迁移只允许向前新增表、索引和策略。
- 旧 `/api/acceptance/overview` 与当前生产服务在正式切换前保持不变。
- 身份功能不完整或对应源码交付不完整时，隔离候选停止在不可公开状态。
