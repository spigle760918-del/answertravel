# ADR：AnswerTravel 最终产品界面与实施前冻结

状态：界面 Gate E 已确认，实施尚未授权

日期：2026-09-20

决策类型：产品信息架构、页面契约与实施顺序冻结

关联决策：`45-platform-customer-boundary-adr.md`、`47-geoflow-aligned-product-ui-intent-card.md`、`48-geoflow-agpl-frontend-integration-adr.md`、`49-product-scope-convergence-adr.md`

## 1. 最终产品定义

AnswerTravel 是面向多个文旅品牌的 GEO 监测与决策平台。它监测品牌所关心的游客问题在真实 AI 平台上得到什么回答、品牌和竞品如何被描述、回答使用了哪些可核验信源，并据此决定内容、官网、信源、品牌事实或业务改进方向，再按同口径复测。

唯一主闭环固定为：

```text
品牌真相
→ 游客问题
→ 多平台真实监测
→ 原始回答与引用/信源证据
→ 品牌、竞争对手与问题表现分析
→ 根因诊断
→ 内容/官网/信源/业务决策
→ 受控行动
→ 同口径复测
```

面向用户的一句话表达固定为：

> 监测品牌所关心的游客问题，分析信源和竞品，决定内容方向。

“决定内容方向”不等于每次都生成内容。证据不足、真实产品差距、官网结构问题、外部信源不足或模型波动时，系统必须分别建议补采、改业务、修页面、建可信信源或暂不行动。

## 2. 设计与平台边界

- GEOFlow 固定版本 `abcc638887dd35f508a59815f01ed42bc4415a09` 只提供设计系统、页面母版和成熟交互；不继承其完整功能范围。
- 实际复用和修改的 GEOFlow 前端代码按 AGPL-3.0-only 单独开源并保留许可证、版权、源码入口和上游版本记录。
- AnswerTravel 的 TypeScript、PostgreSQL、Redis、队列、租户隔离、证据链、预算和授权门禁继续作为业务事实源。
- 北京珈程只是一组真实租户数据和验收案例，不出现在通用栏目、规则或默认文案中。
- 原工程验收台降级为平台管理员入口；CI、Docker、迁移、备份和服务器门禁不进入客户主导航。

## 3. 冻结的信息架构

### 3.1 全局入口

| 入口 | 页面目的 | 核心交互 |
| --- | --- | --- |
| AI 工作台 | 用一句业务任务调用已有能力 | 理解任务 → 选择 Skill → 校验权限/预算 → 预览计划 → 等待确认 → 执行 → 返回证据结果 |
| 当前品牌空间 | 明确所有数据所属租户 | 展示真实租户；没有切换能力时不得伪装为切换器 |
| 平台管理 | 管理租户、成员、权限、Provider、预算、Skill/Prompt 和审计 | 独立管理员入口，不混入客户工作台 |

AI 工作台不是无约束聊天、自动训练系统或通用内容助手。它只能编排已有、版本化、可审计的 AnswerTravel 能力。

### 3.2 客户产品导航

```text
总览

AI 监测
├─ 游客提问分析
├─ 游客问题管理
├─ 监测计划
├─ 周期监测
├─ 采集渠道
└─ 运行记录（含失败与费用）

数据分析
├─ AI 可见性
├─ 竞争对手分析
├─ 问题表现分析
├─ AI 平台比较
├─ 引用与来源
└─ 历史变化

证据
├─ 原始回答
├─ 引用来源
├─ 页面快照
└─ 证据包

决策与行动
复测

品牌真相
├─ 品牌与服务事实
├─ 品牌名称与别名
├─ 竞争范围
└─ 事实版本
```

“失败与费用”属于运行记录的筛选、摘要和详情，不形成永久独立导航。

## 4. 冻结页面清单与真实数据映射

### 4.1 总览

用户结果：快速回答“现在监测什么、发生了什么变化、哪些问题值得处理、下一步是什么”。

只显示有真实证据的内容：当前批准问题组、有效监测周期、成功/失败样本、预算消耗、品牌与竞品主要变化、信源变化、待确认决策和复测结果。数据来自问题组、观察计划/目标/尝试/回答、GEO 分析、诊断、行动和观察周期。

不得显示工程上线清单，也不得把一次采样包装为趋势。

### 4.2 游客提问分析

用户结果：从单个问题出发，看到该问题在各平台和轮次中的回答、品牌/竞品表现、引用信源、变化和建议方向。

真实映射：`question_panels`、`observation_targets`、`raw_answers`、`geo_analysis_runs`、`geo_entity_mentions`、`geo_ranking_facts`、`geo_claim_facts`、`citation_events`、`source_snapshots`、诊断与行动建议。

页面必须能下钻到原始回答；不能只显示汇总分数。

### 4.3 游客问题管理

用户结果：维护品牌真正关心的问题及版本，而不是维护通用关键词库。

显示字段：问题文本、问题类型、中性/品牌/竞对分组、旅前阶段、人群/场景、是否纳入、来源、状态、所属问题组版本和变更原因。真实映射以 `question-intelligence` 与不可变 `question_panels` 为基础。

批准后生成新版本，历史版本不可覆盖。中性问题、品牌问题和竞对深挖问题必须分开计算。

### 4.4 监测计划与新建计划

用户结果：选择已批准问题组、真实采集渠道、轮次、语言/区域、预算和执行窗口，并在付费或高风险执行前确认。

真实映射：`observation_plans`、`observation_targets`、采样规则、授权标记、Provider/模型/终端适配器和队列任务。

当前生产能力只支持 DeepSeek API；其他平台或网页终端只有在对应适配器、授权与验收存在后才可选择。禁用项应说明原因，不得伪装为已接入。

### 4.5 周期监测

用户结果：按固定口径持续产生监测周期，并知道下次何时运行、每周期预算和最近结果。

真实映射：`monitoring_schedules`、`monitoring_cycles` 和对应观察计划。当前后端只支持固定的每日 DeepSeek API 计划；界面不得提前提供未实现的周/月复杂排程、多平台轮换或任意终端组合。

创建、暂停、恢复、修改预算等写操作必须逐项核对现有后端契约；没有真实命令时先只读展示。

### 4.6 采集渠道

用户结果：理解答案从哪里、以什么方式取得，并判断当前渠道是否可用。

每个渠道显示：AI 平台、采集方式（官方 API 或获授权终端）、模型/版本、区域语言、认证状态、支持能力、最近验证、限制和成本口径。

网页/App 终端采样必须是独立适配器并遵守授权、条款、速率和风控。不得使用反检测手段；不得把规划中的渠道显示为可运行。

### 4.7 运行记录（含失败与费用）与详情

用户结果：查看每次计划是否完成、哪些目标失败、花费多少、产出哪些证据，并能对失败作合规处理。

真实映射：`observation_plans`、`observation_targets`、`observation_attempts`、`raw_answers` 和队列状态。字段包括计划、问题组版本、渠道、模型、轮次、目标数、成功/失败数、错误代码、HTTP 状态、Token、时间、授权和关联证据。

失败记录必须保留。重试或补采创建新尝试/新计划，不删除或改写历史失败。

### 4.8 AI 可见性

用户结果：在明确样本口径下理解品牌是否自然出现、如何被描述、是否被推荐以及证据是否充分。

真实映射：`geo_analysis_runs`、`geo_entity_mentions`、`geo_ranking_facts`、`geo_claim_facts`。提及、推荐、主张与情感必须分开；排名只在回答存在明确有序列表时显示，否则为“不适用”。

### 4.9 竞争对手分析

用户结果：在同一问题、平台、终端、区域、时间窗和轮次下比较品牌与已确认竞品。

必须覆盖：自然提及、推荐情况、适用时的条件排名、AI 描述/主张、引用与信源差异，并可按问题、平台和原始回答下钻。

现有 `geo_entity_sets`、`geo_entity_mentions`、`geo_ranking_facts`、`geo_claim_facts` 可支持实体分析，但尚缺完整的“竞争范围”业务契约。实施本页写功能前必须先建立直接竞品/本地竞品/替代方案、业务重叠、区域、有效期、确认人和版本历史；不得把一个孤立表单直接接入生产。

### 4.10 问题表现分析

用户结果：识别哪些游客问题最常出现品牌缺席、竞品领先、风险主张或信源不足，并决定先处理哪个问题。

由问题与真实回答、GEO 事实、引用事实和诊断结果聚合。排序必须显示有效样本和不确定性，不能创造没有指标契约的“机会分”。

### 4.11 AI 平台比较

用户结果：比较同一问题在不同已接入平台上的表现差异。

仅当至少两个真实平台在统一分析口径下都有有效样本时展示对比；当前单 DeepSeek 数据只能显示“暂无可比较的第二平台”，不得生成模拟对比。

### 4.12 引用与来源

用户结果：知道回答中出现了哪些链接候选、哪些页面可访问、品牌与竞品依赖哪些来源，以及哪些结论仍证据不足。

真实映射：`citation_scans`、`citation_events`、`source_snapshots`。必须区分正文链接、来源列表、Provider 结构化引用和内容吸收候选。

当前 DeepSeek API 路径没有可核验的结构化引用保证。回答文本中的 URL 只能标为“链接候选”，抓取成功也不能自动证明模型依据了该页面。

### 4.13 历史变化

用户结果：按可比较周期查看品牌、竞品、问题和信源发生了什么变化。

真实映射：可比较观察周期、观察计划、GEO 分析和结果快照。口径变化时必须中断趋势线或明确标记“不可直接比较”，不得拼接不同问题组、模型或采集方式形成虚假趋势。

### 4.14 原始回答

用户结果：核对模型实际回答和完整采集上下文。

真实映射：`raw_answers`、Provider 原始载荷、`observation_targets`、`observation_attempts`。详情显示问题、回答全文、平台、模型、采集方式、语言/区域、轮次、时间、Token、状态、哈希及后续分析引用。

### 4.15 引用来源与页面快照

用户结果：检查每个链接候选及对应页面的抓取事实。

真实映射：`citation_events` 与 `source_snapshots`。显示规范化 URL、域名、跳转链、HTTP 状态、标题、作者、发布日期、摘录、内容哈希、抓取时间和失败原因。

### 4.16 证据包

用户结果：把某个问题、诊断或决策的原始回答、来源、分析规则和事实等级组成可审计集合。

当前后端已有证据引用关系但没有完整的用户可管理“证据包”聚合契约。第一阶段可以生成只读视图；导出、冻结和分享功能必须在新契约和权限审计完成后实施。

### 4.17 决策与行动

用户结果：从证据看到根因、替代解释、缺失证据、可选动作、“不行动”选项、风险、负责人、审批和验证计划。

真实映射：`geo_diagnosis_snapshots`、`geo_action_proposals`、竞对深挖建议、证据缺口路由、优化行动计划、事实补充、官网诊断与修复蓝图。

内容方向只是动作类型之一。任何写作、页面或信源任务都必须来自具体诊断并关联证据、事实边界、审批、回执和复测；不得扩张成通用内容工厂。

### 4.18 复测

用户结果：使用原问题组和同口径条件检查行动后发生了什么变化，并看到可比性和归因限制。

真实映射：可比较观察周期、前后计划、结果快照和复诊。必须显示基线、复测窗口、口径差异、有效/失败样本和不确定性；没有实验设计时只能报告关联，不宣称因果。

### 4.19 品牌与服务事实、名称与别名、事实版本

用户结果：维护监测、识别和决策所依赖的企业真相。

真实映射：`brand_truth_cards`、品牌事实、状态、事实等级、公开范围、来源和不可变版本。名称与别名需要作为通用租户契约补齐，不能继续隐藏在客户常量或仅存在于 GEO 实体集。

### 4.20 竞争范围

用户结果：明确“系统拿谁比较、为什么比较、在哪个区域和时期有效”。

实施前必须新增版本化业务契约，至少包含：实体、别名、关系类型、重叠业务、区域、有效起止时间、证据/说明、确认人、状态和版本。它为问题组、实体识别和竞争对手分析共同提供输入，不是一个只影响界面的设置表单。

## 5. 统一分析口径条

所有汇总、分析、诊断、竞品和复测页面顶部必须使用同一个“分析口径”组件，并显示：

- 当前品牌空间；
- 问题组及版本；
- 问题类型；
- AI 平台；
- 采集方式/终端；
- 模型及版本；
- 语言与区域；
- 时间窗口；
- 轮次；
- 有效样本和失败样本；
- 分析规则版本；
- 可比较性与不确定性状态。

任何筛选改变口径时，指标、表格、证据链接和导出范围必须一起改变。口径不完整时，页面不得显示看似精确的结论。

## 6. 页面状态契约

每个页面必须实现以下真实状态，不能用示例数据掩盖：

| 状态 | 用户可见表达 | 允许操作 |
| --- | --- | --- |
| 加载中 | 保持固定布局的骨架与当前筛选条件 | 可取消或返回，不闪现旧租户数据 |
| 首次无数据 | 说明缺少的前置步骤和唯一下一步 | 只提供有权限、后端已支持的动作 |
| 筛选无结果 | 明确“当前筛选无记录”，保留清除筛选 | 不暗示系统无数据 |
| 证据不足 | 显示缺少的样本/周期/信源和“不确定” | 补采或等待，不给确定性结论 |
| 不可比较 | 显示具体口径差异 | 可查看各期，不计算变化率 |
| 部分成功 | 同时显示成功、失败和影响范围 | 下钻失败，受控补采 |
| 错误 | 人能理解的失败原因和事件编号 | 重试只产生新记录，不覆盖历史 |
| 无权限 | 说明缺少的角色或授权 | 不展示敏感数据，不提供假按钮 |
| 能力未接入 | 标明当前不可用及真实前置条件 | 不允许选择或保存 |
| 待人工确认 | 显示计划、预算、风险和证据 | 明确 Yes/No，不自动执行 |

租户切换、返回、刷新和错误恢复均不得短暂显示上一租户数据。

## 7. 明确排除

以下功能不实施，也不留客户可见占位或“以后再做”的接口：

- 通用 CMS、建站与主题装修；
- 与 GEO 诊断无关的内容工厂；
- 关键词库、标题库、图片库和通用素材库；
- 多站群 SEO 分发；
- 通用流量/广告归因；
- 线索、CRM、销售漏斗和订单；
- 无证据来源的竞品榜单、模拟趋势和模拟平台数据；
- 自动学习并自行扩大权限、预算或任务范围的聊天机器人。

## 8. 实施分期

### 第 0 期：施工意图卡与契约冻结

- 新建独立实施意图卡，明确首批页面、API、认证、AGPL 源码交付和回滚。
- 固定统一分析口径对象、页面状态对象和客户字面量扫描规则。
- 只允许文档、契约与测试设计；需再次通过 Gate A 才能改运行代码。

### 第 1 期：产品壳层与只读证据闭环

- 实施 GEOFlow 对齐壳层、真实路由、租户上下文和权限边界。
- 首批页面：总览、游客问题管理、监测计划/运行记录、原始回答详情。
- 建立页面级 API，停止让全部客户页面依赖 `/api/acceptance/overview`。
- 旧验收台保留为独立管理员入口和回滚路径。

### 第 2 期：分析与证据

- 实施 AI 可见性、问题表现、引用与信源、页面快照及统一口径条。
- 先使用现有真实数据；没有第二平台时显示诚实空状态。
- 补齐只读证据包聚合契约。

### 第 3 期：竞争范围与竞争对手分析

- 先实现版本化竞争范围后端契约、第二租户测试和数据迁移。
- 再实施竞争范围管理、竞争对手分析和按问题/平台/回答下钻。
- 严禁先做孤立 UI 表单或用固定珈程竞品填充。

### 第 4 期：诊断、决策、行动与复测

- 实施根因、替代解释、证据不足、动作审批、回执、回滚和同口径复测。
- 内容方向作为诊断动作呈现，不建立通用 CMS。
- 所有真实执行继续由独立权限、预算和发布门禁控制。

### 第 5 期：周期监测与变化提醒

- 先只展示当前真实日频 DeepSeek 能力。
- 写操作和更多排程只有在后端契约与恢复测试完成后开放。
- 提醒只针对有意义的变化、失败或需人工处理的事项；正常无变化时保持安静。

## 9. 实施验收与回滚门禁

每一期必须分别通过：

1. 产品门禁：页面目的与本 ADR 一致，没有范围膨胀；
2. 数据门禁：所有数字可下钻到真实回答、采集上下文和规则版本；
3. 多租户门禁：至少两个不同品牌 fixture，无客户数据串租户；
4. 诚实状态门禁：空、错、无权限、证据不足和不可比较可复现；
5. 权限与费用门禁：写操作、付费采样和发布不会因 UI 切换被绕过；
6. AGPL 门禁：源码、许可证、版权、版本和修改记录可获得；
7. 交互门禁：桌面与移动视口无重叠，主要列表、详情、抽屉和确认流程可用；
8. 回滚门禁：新前端可按版本回退，旧管理员验收入口和历史证据不被删除；
9. 用户 Gate E：每一期生产切换前由用户确认真实界面。

## 10. 本次确认的边界

2026-09-20，用户在逐页预览并补齐游客问题、采集渠道、失败与费用、竞品范围、信源分析和内容方向后回复“好的”“yes”，确认本 ADR 所记录的产品方向和实施前冻结。

本次确认：

- 确认最终信息架构、页面目的、GEOFlow 交互方向和实施顺序；
- 结束界面原型 Gate E，允许编写下一份实施意图卡；
- 不等于授权修改 `v2` 运行代码；
- 不授权部署生产、调用 DeepSeek、创建周期任务、修改客户官网或发布内容；
- 不改变历史生产数据、授权和失败证据。

下一步必须先提交“首批产品壳层与只读证据闭环实施意图卡”，经用户 Gate A 确认后才能施工。
