# 观察编排意图卡：DeepSeek API 真实答案采集与不可变证据

状态：Gate A 待用户确认
日期：2026-09-14

## 用户问题

已批准的问题组需要按确定的轮次自动向 DeepSeek API 提问，并保存每一次真实回答、原始响应、上下文、用量和失败。系统必须能够重复运行、失败重试和恢复，同时保证后续任何提及率或品牌描述都能下钻到原始答案。

## 本切片输入

- 已批准且不可覆盖的 `QuestionPanelVersion`；
- 仅处理问题组中 `included=true` 的问题；
- Provider：DeepSeek API，默认模型 `deepseek-chat`；
- 终端标识固定为 `api`，不得标记为 Web、App 或联网搜索；
- 采样轮次、语言、地区上下文、温度、最大输出、并发、超时、重试和费用上限；
- 版本化采样规则和幂等键。

## 本切片输出

- 版本化 `ObservationPlan`：问题组版本、采样规则、计划样本数、预算和运行窗口；
- 持久队列任务：每个“问题 × 轮次”一个可恢复任务，定时器只产生计划，不充当状态事实源；
- `ObservationRun` 与每次尝试的最终状态：等待、运行、成功、失败或因预算停止；
- 不可变 `RawAnswer`：回答正文、DeepSeek 原始响应、请求上下文、模型、API 终端、时间、地区/语言、耗时、用量、结束原因和哈希；
- 不可变失败证据：超时、限流、HTTP 错误、空正文、截断和网络错误；
- 完整审计、幂等结果及计划级成功数、失败数、总用量和实际费用基础数据。

## 关键数据与证据边界

- 每个成功样本必须关联问题组版本、问题候选 ID、采样轮次、Provider、模型、终端和采样规则版本；
- 原始回答和 Provider 响应只能追加，不能修改、删除或用重试结果覆盖；
- 重试必须作为独立尝试记录；同一幂等键不得产生两个“有效成功样本”；
- 无正文、截断或协议无效的响应不得计为有效回答；
- DeepSeek API 未返回结构化引用时记录“该终端未提供引用”，不得伪造引用；回答正文中出现 URL 只保留为原文，暂不判定为引用；
- 地区是调用时传入的上下文标签，不得声称代表 DeepSeek 实际机房或用户定位。

## 自动化与人的边界

- AI/系统自动产生任务、控制并发、执行采样、限流重试、记录成本和恢复失败任务；
- 达到预算上限、密钥无效、连续 Provider 故障或数据完整性异常时自动停止并告警；
- 人只确认采样计划的预算/问题组，并处理密钥、账户余额或 Provider 授权异常；
- 本切片不要求人逐题点击采集，也不允许人为补写或修改回答。

## 验收场景

1. 正常：使用已批准的隔离测试问题组，真实 DeepSeek API 完成多问题、多轮次采样，每个回答可下钻至完整原始证据。
2. 幂等：相同问题、轮次、问题组版本和规则版本重复入队，不产生第二个有效样本。
3. 重试：429/5xx/网络失败按策略重试，每次尝试可见；最终成功不覆盖之前失败。
4. 预算：预计或累计用量达到上限后，剩余任务进入明确停止状态，不继续调用。
5. 无效回答：空正文、`finish_reason=length`、协议错误和超时不进入有效样本分母。
6. 恢复：Worker 在任务执行前后异常退出，持久队列可恢复，数据库状态与审计不产生伪成功。
7. 隔离：跨租户不可见；测试数据与未来真实品牌数据严格隔离。
8. 终端：所有本切片样本显示 `DeepSeek API`，不得显示为 DeepSeek 搜索、Web 或 App。

## 非目标

- 不计算品牌/竞品提及率、排名、情感、引用或趋势；
- 不抓取引用来源、官网或第三方文章；
- 不生成内容方向、文章或发布任务；
- 不接入 DeepSeek Web/App、豆包、千问、Kimi、元宝等其他终端；
- 不导入真实业务品牌资料，真实品牌试运行在后续整体验收门禁执行。

## Gate A 后的实施顺序

1. 固定计划、任务、尝试、原始回答、用量、费用基础和失败状态契约；
2. 固定正常、幂等、重试、预算、恢复、隔离和无效回答样例；
3. 实现 PostgreSQL 状态、BullMQ 持久任务、DeepSeek Adapter 和不可变证据的最小真实路径；
4. 使用隔离测试问题组完成真实 DeepSeek 多问题采样，本地完整测试与 Linux CI；
5. 未经 Gate A 确认不得编码，未经 Gate E 确认不得进入基础 GEO 情报计算。
