# 意图卡：证据缺口聚类、优先级与优化动作路由 V1

状态：Gate A-D 已完成，Gate E 待用户验收
日期：2026-09-15

## 为什么现在做

品牌描述核验得到 57 条“证据不足”主张，但“证据不足”不等于负面，也不等于都需要写文章。系统应先识别游客真正关心的主题、重复频率和业务价值，再将缺口路由到正确动作：补品牌资料、修官网结构、建设第三方信源、改进真实产品服务、形成内容任务书，或暂不行动。

## 输入

- 36 条品牌直问回答及按 `brand-claim-verification.v2` 重新生成的 83 条逐条核验主张；
- 57 条证据不足、0 条仅品牌自述、26 条事实一致和 0 条事实冲突结果；
- 已批准品牌真相、官网快照、产品事实、禁用表达和公开范围；
- 问题角色、旅前阶段、问题主题、采样周期和引用状态。

## 输出

1. 将证据不足主张聚类到游客决策主题：产品行程、价格费用、纯玩承诺、资质可信度、老人亲子适配、定制能力、退款取消、门票/天气应急及其他；
2. 为每个主题计算可复算优先级，至少考虑出现频率、跨周期重复、对应问题重要性、现有事实覆盖和风险等级；
3. 区分根因与动作路由：
   - 品牌事实缺口：请求负责人补充最少事实；
   - 官网证据结构缺口：提出页面/FAQ/结构化事实改造；
   - 外部信源缺口：提出可验证的机构、平台、合作方或媒体证据建设；
   - 产品服务缺口：转成人工业务改进，不用内容掩盖；
   - 表达或采样波动：暂不行动并继续观察；
4. 每个主题输出事实等级、证据数量、推荐动作、不行动选项、预计成本/风险/窗口和需要人的最少信息；
5. 只有达到内容条件的主题才生成“内容任务书候选”，本切片不生成正文；
6. 验收台展示优先级列表及“为什么做/为什么不做”。

## 自动化边界

- AI 自动聚类、评分、路由和生成建议；
- 确定性规则优先，语义聚类无法可靠判断时归入“待复核”，不硬分；
- 不因高频出现就把未经核验的主张写入品牌真相；
- 不自动要求用户逐条处理 57 项，只汇总成少量主题和最少补充问题；
- 不启动竞品直问、多模型采样、内容正文生成或发布；
- 涉及产品能力、退款承诺和高风险公开表达时必须后续 Yes/No。

## 验收标准

1. 57 条证据不足主张均可追溯且被归组或标记待复核；
2. 相同主张跨周期不会被重复放大计数；
3. 优先级公式版本化、可复算，事实与建议明确分级；
4. 至少能区分“补事实、修官网、建信源、改业务、写内容、暂不行动”；
5. 不把 0 个事实冲突误写成舆情危机；
6. 页面只向文旅负责人提出少量、明确、可回答的问题。

## 非目标

- 不生成完整优化文章或页面；
- 不发布到官网、小红书、网易、携程等渠道；
- 不评价竞品服务质量，不启动竞品深挖；
- 不宣称内容动作会导致 AI 提及率提升。
