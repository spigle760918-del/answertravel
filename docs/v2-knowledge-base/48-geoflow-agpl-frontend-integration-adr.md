# GEOFlow AGPL 前端集成 ADR

状态：界面与集成方向已确认，待独立实施意图卡 Gate A

日期：2026-09-17

## 1. 决策

AnswerTravel 前端以 GEOFlow 固定版本 `abcc638887dd35f508a59815f01ed42bc4415a09` 的设计系统和成熟交互为母版，按 AGPL-3.0-only 方式维护实际复用和修改的对应源码。GEOFlow 的完整功能范围和原始一级栏目不再照搬。AnswerTravel 已有 TypeScript、PostgreSQL、Redis、队列和证据链后端保留为独立服务，通过版本化 HTTP API 与前端通信。

## 2. 被否决方案

- 继续维护当前绿色工程验收台；
- 只参考 GEOFlow 风格、重新设计 AnswerTravel 一级导航；
- 在闭源 React 目录中复制 GEOFlow 的 Blade、JavaScript 或 CSS；
- 为追求统一技术栈而推倒已经验证的 AnswerTravel 后端。

## 3. 前端边界

AGPL 前端层包括：

- GEOFlow 公共侧栏、顶栏、账户区和响应式壳层；
- 页面标题、局部导航、指标、筛选、表格、表单、详情、状态、弹窗和 Toast；
- AI 工作台，以及围绕观察、证据、诊断、决策、行动、复测和品牌真相形成的客户页面；
- 为接入 AnswerTravel API 所做的前端修改与适配代码。

该层必须保留许可证、版权与源码获取入口，构建和部署产物可追溯至固定上游版本及本地修改记录。

## 4. 后端边界

保留 AnswerTravel 现有业务后端：

- 多租户与 PostgreSQL RLS；
- 品牌真相、问题、观察、原始回答和来源证据；
- GEO 诊断、行动、审批、发布回执和复测；
- BullMQ/Redis 队列、Provider 适配器、预算和授权门禁；
- 不可变审计及事实等级。

GEOFlow 前端不得绕过后端租户、授权、事实和发布门禁，也不得把演示数据写入生产路径。

## 5. 集成方式

- 前端与后端分别构建、分别测试、分别声明许可证；
- 前端只调用公开、版本化的 AnswerTravel API；
- 身份、租户、权限、CSRF/CORS 和会话边界在实施意图卡中单独确定；
- 第一阶段不把 PHP/Laravel 数据模型替换为 AnswerTravel 事实源，也不双写两套业务数据库；
- 原验收台降级为平台内部管理入口，不再作为客户产品首页。

## 6. 施工门禁

1. 直接依据原始源码生成完整界面预览；
2. 用户确认视觉、导航和页面母版 Gate E；
3. 固定 AGPL 源码交付与署名方案；
4. 定义最小 API 映射和认证方案；
5. 分阶段施工，首批只替换公共壳层和只读数据中心；
6. 每阶段保留旧入口回滚能力，不修改历史生产证据。
