# AnswerTravel V2 总体架构基线

状态：已确认  
版本：1.0  
日期：2026-09-13

## 1. 架构选择

推荐采用“模块化单体 + 异步任务 + 可插拔适配器”，先保证模块边界和端到端证据链，暂不一开始拆微服务。

理由：

- 当前团队和行业用户规模适合降低部署及运维复杂度；
- 模块化边界仍允许采集、抓取、生成等重任务独立扩展；
- 未来高负载模块可按实际证据拆出，不靠猜测提前拆分；
- 对 Vibe Coding 更友好，每次能完成一个真实垂直切片。

## 2. 业务模块

| 模块 | 唯一职责 | 明确不负责 |
| --- | --- | --- |
| 组织与策略 | 用户、品牌空间、权限、预算、自治等级 | GEO 指标计算 |
| 品牌真相中心 | 品牌实体、产品服务、差异化、事实卡、禁用表达、证据 | 采集模型回答 |
| 问题智能 | AI 拓题、意图簇、旅程阶段、去重、评分、问题组版本 | 调用采样平台 |
| 观察编排 | 计划、队列、并发、重试、限流、成本和 Provider/终端适配 | 品牌优劣决策 |
| 原始证据仓 | 不可变回答、原始响应、模型/终端/时间/区域、截图和哈希 | 改写原始回答 |
| 引用与信源 | URL 规范化、来源抓取、页面快照、作者日期、引用选择/吸收 | 生成营销内容 |
| GEO 情报 | 提及、条件化排名、主张情感、风险、竞品、网站和趋势 | 直接发布文章 |
| 决策引擎 | 机会评分、根因判断、竞对深挖触发、动作编排 | 绕过审批执行高风险动作 |

## 3. 平台支撑模块

- 审计与溯源：记录每个结论由哪些回答、来源、算法、Prompt 和模型版本产生。
- 可观察性：任务成功率、耗时、费用、限流、失败类型和数据新鲜度。
- 安全与合规：租户隔离、密钥托管、SSRF 防护、敏感数据、发布权限和审计日志。
- 质量评测：问题拓展、实体识别、排名、情感、引用吸收、决策、内容事实性评测集。
- 版本与迁移：Schema、指标、Prompt、Skill、Provider、文章和实验均版本化。

## 4. 核心数据链

```text
BrandTruthVersion
  → QuestionPanelVersion
  → ObservationRun
  → RawAnswer + RawProviderPayload
  → CitationEvent + SourceSnapshot
  → MetricFact
  → DiagnosisSnapshot
  → ActionProposal
  → ApprovalDecision
  → Content/Website/Source Action
  → PublishReceipt
  → MeasurementCohort
  → OutcomeSnapshot
```

任何看板数字都必须能够反向下钻至 `RawAnswer` 和采集上下文；任何内容必须反向关联到 `DiagnosisSnapshot`、品牌事实与来源证据。

## 5. 决策引擎动作分类

分析落后于竞品时，AI 不能默认“写文章”，必须先选择根因：

1. 样本或采集不足：扩大重复采样或增加终端；
2. 品牌实体/事实缺口：补充和统一品牌真相；
3. 产品服务真实差距：转成人工业务改进任务；
4. 官网技术/页面结构差距：修复抓取、Schema、结构和事实颗粒度；
5. 内容覆盖差距：新建、重写或扩展内容集群；
6. 外部信源差距：建设可验证的媒体、机构、合作方或用户证据；
7. 口碑与风险差距：先处理真实服务和公开回应；
8. 模型波动：观察而不行动；
9. 竞对原因不清：触发竞对深度问题组和新一轮采样。

## 6. 竞对深度追踪

竞对追踪是决策引擎的按需子流程，不是所有竞品每天无限采集。

建议触发条件：

- 同口径提及率或排名连续两个有效周期落后；
- 置信区间显示差距具有实质意义；
- 竞品引用份额、外部权威信源或页面吸收显著领先；
- 竞品发布重大产品/内容/热点动作；
- AI 无法从首轮样本解释差距。

深挖问题包括“竞对怎么样/靠谱吗/适合谁/优缺点/与品牌对比”等，但必须与中性问题分开计算，不能污染主监测指标。

## 7. 热点到品牌动作

设置“热点机会雷达”：

1. 获取文旅、目的地、天气、节庆、交通和公共事件；
2. 匹配品牌真实能力、产品和服务；
3. 检查事实完备度、敏感性、时效和合规风险；
4. AI 提出“不响应/解释/服务动作/内容动作/页面动作”选项；
5. 人只补充品牌实际行动并 Yes/No；
6. AI 生成并执行获批内容，随后建立短周期复测。

## 8. 已确认技术形态（非业务人员无需逐项决定）

- 主系统使用 TypeScript，目标运行时为 Node.js 24.x LTS；
- 全栈类型安全的 Web 应用，模块化后端；
- PostgreSQL 保存业务事实和指标，向量能力只用于明确需要的语义任务；
- Redis/持久化队列承载采集、抓取、生成和发布任务；
- 对象存储保存原始响应、页面快照、截图和大文件；
- Provider/Publisher/Source Fetcher 均为版本化适配器；
- OpenTelemetry 或等价方案统一日志、指标和链路；
- 统计或研究型任务可使用独立 Python Worker，但 Python 不作为主业务运行时；
- 开发、测试和生产统一使用 PostgreSQL，不使用 SQLite 作为过渡业务数据库；
- 官方 API 优先，获授权网页/App 采样作为独立终端适配器；不得绕过验证码、访问控制或平台风控。

Web 框架、数据库访问层和队列库在 Phase 1 技术 Spike 后固定，选择标准是可维护、可测试、可替换和团队可承受，而不是追逐最新框架。

## 9. 外部项目在架构中的位置

- GEOFlow：内容知识库、审核、站点/WordPress 分发和运营工作流参考；AGPL 代码不默认并入闭源核心。
- yao-geo-skills：问题拓展、全景诊断、监测、品牌知识、页面与内容产物的契约和评测参考。
- geo-citation-lab：引用选择/吸收、跨模型/终端和页面特征研究基线。
- yao-open-prompts：Prompt 候选素材；进入生产前必须版本化和评测。
- yao-meta-skill：Skill IR、触发评测、证据台账、发布门禁和漂移治理方法。
- yao-open-skills：可选的决策、定位、安全和内容交付能力，不作为核心运行时。
