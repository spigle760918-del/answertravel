# 意图卡：引用与信源证据 V1

状态：Gate A 待用户确认  
日期：2026-09-14

## 用户问题

系统需要回答“AI 为什么这样描述品牌、引用了谁、哪些域名和文章经常成为信源”。在计算高引用域名、竞品信源差距或选择范文前，必须先区分：回答里出现网址、模型列出来源、Provider 返回结构化引用、来源内容可能被答案吸收。这些不是同一件事，不能把任意链接直接算成引用。

## 本切片输入

- 已保存的不可变 AI 原始回答、Provider 原始响应和采集上下文；
- 回答中出现的 URL、域名、来源名称或 Provider 结构化引用字段；
- 租户、品牌空间、模型、终端、问题、轮次和采集时间；
- 已确认的抓取授权、速率、域名限制和安全策略。

## 本切片输出

1. 版本化的引用候选事件：证据类型、原始 URL、规范 URL、域名、关联回答和证据强度；
2. 明确区分 `正文链接`、`来源列表`、`Provider 结构化引用`、`内容吸收候选`；
3. 合规可访问页面的来源快照：标题、作者、发布日期、正文摘要、抓取时间、状态和内容哈希；
4. 无引用、无法访问、重定向、超时、拒绝访问、证据不足和不适用状态；
5. 验收台中的“回答 → 引用候选 → 来源页面证据”只读下钻。

## AI 与人的分工

- AI 自动提取、规范化、去重、排队抓取、保存快照并判断证据等级；证据不足时返回“不确定”或“尚不能判定为引用”。
- 人不逐条整理链接；只确认抓取政策、授权边界和必须排除或允许的特殊域名。
- 本切片自治等级为 A0 观察；不对外发布、不修改来源页面。

## 安全与事实边界

- 只访问公开且获准的 HTTP/HTTPS 页面；执行 SSRF、私网地址、重定向、文件类型、大小、超时和速率限制。
- 不绕过登录、验证码、付费墙、robots、平台风控或访问控制。
- 页面正文和元数据按抓取时点保存哈希；历史快照不可覆盖。
- DeepSeek API 当前没有返回引用且回答中没有 URL 时，必须显示“未发现引用证据”，不能推导虚假来源。
- “内容吸收”只是待验证关系；没有可复算方法和足够证据时不得宣称来源文章影响了模型回答。

## 验收场景

1. 对真实保存的 DeepSeek API 回答逐条处理；有链接则形成可追溯候选，无链接则明确显示零证据状态。
2. 同一 URL 的参数、锚点、大小写和重定向得到稳定规范结果，同时保留原始值。
3. 来源页面成功时可从回答下钻到快照、时间和哈希；失败时展示具体失败类型，不伪造正文。
4. 私网地址、非 HTTP 协议、超限页面、重定向到禁止地址和未授权页面被安全拒绝。
5. 租户隔离、幂等、重试、速率、审计、不可变证据和恢复测试通过。
6. 浏览器页面不返回密钥、认证头、内部地址或未授权敏感正文。
7. Gate E 由用户实际查看“回答—引用—来源”下钻和无证据/失败状态后 Yes/No。

## 非目标

- 不在本切片计算品牌提及率、排名、情感、引用份额、高引用域名趋势或竞品胜负；
- 不生成文章、不选择范文、不发布内容；
- 不接入 DeepSeek Web/App 或新增第二个模型终端；
- 不把页面相似度直接等同于引用或因果影响。

## 通过 Gate A 后的实施顺序

1. 固定引用事件、来源快照、抓取任务和失败状态契约；
2. 建立 URL 规范化与安全抓取边界；
3. 完成原始回答到引用候选和来源快照的最小真实链路；
4. 增加验收台下钻、空状态和失败状态；
5. 完成契约、租户、安全、幂等、恢复、浏览器和敏感信息测试；
6. Gate E 实际网页验收，通过后再进入品牌/竞品基础 GEO 指标切片。
