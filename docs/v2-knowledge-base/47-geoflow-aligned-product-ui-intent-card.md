# AnswerTravel V2 GEOFlow 对标产品界面重设计意图卡

状态：Gate A 设计中，用户确认前禁止施工

日期：2026-09-17

## 1. 触发原因

当前 Web 是随工程切片累积的绿色验收台，把客户业务、生产门禁、CI、备份和告警混在同一产品外壳中。用户重新确认：GEOFlow 提供的不只是运营与发布流程参考，也是 AnswerTravel 前端用户体验、信息架构、视觉风格和布局标准。现状与该初衷背离。

## 2. 本轮目标

先完成一套可查看、可切换主要页面的全局产品原型，让用户在任何运行代码变更前确认：

- 平台与单个客户/品牌空间的层级；
- 主导航、栏目名称与业务顺序；
- AI 工作台、数据、运营、内容资产、分发和系统设置的页面形态；
- GEO 指标、证据、诊断、行动、审批、发布和复测如何串成日常工作流；
- 客户工作台与内部工程验收/平台管理信息如何分离；
- 桌面后台的视觉语言、密度、状态和空状态。

## 3. 已确认的设计基准

GEOFlow 固定版本：`abcc638887dd35f508a59815f01ed42bc4415a09`。

必须继承的体验标准：

- 持久分组左侧导航、简洁顶栏、品牌空间切换与用户入口；
- 白色/浅灰运营后台，蓝色主操作，克制装饰；
- AI 工作台是行动入口；
- 页面标题、短说明、右侧主操作；
- 数据只在有运营意义时形成指标摘要；
- 任务、筛选、表格、队列、审批状态和下一步清晰；
- 内容、数据、分发、系统配置边界明确；
- 不使用营销式渐变 Hero，不以工程 Gate 作为客户主导航。

## 4. AnswerTravel 业务适配

建议一级结构：

1. AI 工作台；
2. 数据中心：GEO 总览、AI 可见度、品牌与竞品、引用与信源、趋势与复测；
3. 运营：监测任务、问题与人群、诊断与机会、优化行动；
4. 内容与资产：品牌知识、内容管理、内容资产；
5. 分发：官网与页面、信源建设、发布与回执；
6. 系统：品牌空间、AI 与 Provider、团队与权限、审计与设置。

导航只表达平台能力，不出现“北京珈程”专属栏目。北京珈程只作为当前选中的真实品牌空间和真实数据实例。

- GEO 总览；
- AI 可见度；
- 品牌与竞品；
- 引用与信源；

- AI/Provider、团队权限和审计设置；
- 内部工程验收入口与客户工作台的隔离表达。

## 6. 本轮非目标

- 不修改 `v2/web/src/App.tsx`、`styles.css` 或任何运行时代码；
- 不连接、不修改生产服务器或北京珈程官网；
- 不进行客户硬编码迁移；
- 不复制 GEOFlow 的 AGPL 源码、组件或品牌素材；
- 不把原型里的示例数值当成生产事实或写入数据库。

## 7. 门禁

- Gate A：用户确认总体信息架构、视觉方向与角色边界；
- Gate B：根据反馈完成全页面交互原型；
- Gate C：逐页检查平台/客户边界、事实等级和权限状态；
- Gate D：形成受控实施拆分、迁移和回滚计划；
- Gate E：用户明确确认最终原型；
- Gate F：Gate E 后才允许创建实施意图卡并修改产品代码。

## 8. 验收标准

- 首次进入即可看出这是多客户 GEO 运营平台，而不是北京珈程专用站或工程验收页；
- 主要工作能从 AI 工作台或任务页进入，并能沿证据到行动、发布和复测闭环；
- 日常客户用户不需要理解 CI、Docker、迁移、备份脚本或内部 Gate；
- 平台管理员仍有独立入口查看运行、审计和部署证据；
- 所有主页面在施工前均可被用户查看和确认。
