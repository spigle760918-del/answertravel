## 需要补充的最小资料

1. 品牌正式名称、常用别名和需要排除的相似名称；
2. 当前正式官网及官方账号；
3. 核心目的地、产品类型、行程/服务范围；
4. 主要服务对象和不适用对象；
5. 真实服务流程、保障和可验证资质；
6. “人无我有、人有我优”的具体事实；
7. 允许公开、仅内部、受限和禁止表达；
8. 主要竞品名称、别名及纳入监控的理由；
9. 禁止生成或发布的承诺、敏感词和合规边界。

## 固定业务规则

- 用户提供的事实进入草案，不自动批准；每条事实保留来源、事实等级、公开范围和有效期。
- “最好、第一、绝对安全、零投诉、全网最低”等无法核验的表达不得直接批准。
- 官网地址必须由用户确认；旧 HTTP 地址不自动升级成 HTTPS，也不自动判断网站安全或归属。
- 竞品名称只建立实体集合，不代表竞品能力、评价或排名。
- 未补齐关键产品/服务事实时，问题组只能保持草案状态；不能采集答案。
- 品牌事实批准与问题组批准分开；每一步只需要一次批量 Yes/No。
- 真实资料不进入公开 Git，不写入日志中的敏感字段，不与隔离验收品牌混用。

## 验收场景

1. 用户能以自然语言一次补充多项资料，系统自动拆成事实卡，不要求工程格式。
2. 每条事实都有来源、公开范围和待确认状态；冲突事实不自动选择。
3. 缺口、敏感词和不可核验主张明确显示。
4. 竞品实体与品牌事实分离，未提供的竞品不由 AI 猜测。
5. 未获品牌事实批准时，真实问题组和答案采样保持锁定。
6. 批准后可生成真实问题组草案，但仍需独立问题组 Gate E。

## 非目标

- 不调用 DeepSeek 进行答案采样；
- 不启动竞对直问或多模型监控；
- 不抓取官网、平台评论或社交账号；
- 不生成、发布或修改内容；
- 不把 V1 历史指标和回答作为真实品牌证据。

## Gate A 通过后的实施顺序

1. 固定事实补充、公开范围、来源和敏感信息契约；
2. 用户补充最小资料，AI 拆分为事实草案；
3. 自动检查冲突、缺口、重复和不可核验主张；
4. 用户批量确认事实和公开范围；
5. 生成真实游客问题组草案；
6. 完成测试、浏览器验收和 Gate E；
7. Gate F 后再建立真实答案采样意图卡。
