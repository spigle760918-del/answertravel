# 意图卡：阿里云资源风险与原生运行决策 V1

状态：Gate A-D 已完成，Gate E 待确认
日期：2026-09-15

## 当前结论

现有 ECS 的 CPU、磁盘和可用内存足以考虑单品牌文本 Alpha，但 swap 已满，且 PostgreSQL、Redis、Node.js 运行时尚未在该主机上形成隔离生产环境。不能把“资源看起来够”直接等同于“可以安全安装”。

## 三条路线

### 路线 A：现有 ECS 原生安装

- 新增 Node.js 24、PostgreSQL 16+、Redis 7+；
- 增加或调整 swap；
- 使用独立用户、独立目录、独立回环端口；
- 优点：不新增云主机；
- 风险：会改变现有主机，安装和资源压力可能影响既有业务；
- 当前状态：需要用户对具体系统变更逐项确认，不能自动执行。

### 路线 B：新增隔离 ECS

- 现有业务服务器保持不动；
- V2 独占新 ECS，使用完整原生部署；
- 优点：隔离最清晰、回滚简单；
- 成本：新增云资源和域名/网络配置。

### 路线 C：外部托管 PostgreSQL/Redis

- ECS 仅运行 API/Worker；
- 数据库和队列使用托管服务；
- 优点：减少本机安装与恢复维护；
- 成本：持续费用、网络白名单和凭据管理更复杂。

## 推荐

默认推荐路线 B；如果必须复用现有 ECS，则先采用“只安装 Node.js 24 + 回环运行探针”，不安装 PostgreSQL/Redis，不接入真实品牌数据，不开放公网，待资源与主机策略确认后再决定。

## 必须人工确认的高风险动作

- 修改或新增 swap；
- 安装系统级 Node.js、PostgreSQL 或 Redis；
- 创建系统用户、服务或计划任务；
- 修改宝塔站点、Nginx、域名解析或 HTTPS；
- 注入 DeepSeek API Key；
- 迁移真实品牌数据到云端。

## 非目标

- 不绕过宝塔安全策略；
- 不在当前阶段声称云端已上线；
- 不因用户的泛化“继续/yes”而推断已批准上述具体系统变更。
