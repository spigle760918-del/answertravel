# 意图卡：品牌个性化行动事实采集框架 V1

状态：Gate A-D 已完成，Gate E 待用户验收
日期：2026-09-15

## 授权依据

用户通过退款政策事实采集 Gate E，并明确要求不要过度固化单一品牌业务细节。优化行动计划的下一行动包为“官网价格与行程事实区”。本切片以该行动包作为首个真实实例，建设可被其他品牌和其他行动包复用的事实采集框架。

## 用户问题

不同文旅品牌关注的产品、价格、行程、服务和证据颗粒度不同，系统如何自动生成个性化补充问题，同时保持事实、来源、时效、公开范围和发布门禁一致？

## 稳定外壳

每条品牌个性化事实都必须包含：

1. 事实值或明确的“不适用/暂缓补充”；
2. 适用产品、人群、渠道或订单范围；
3. 生效时间、有效期或最后更新时间；
4. 原始依据材料或可追溯来源；
5. 公开、内部或受限范围。

## 个性化部分

- 关注主题不由系统写死，来自当前品牌的诊断结果和已批准行动包；
- 本次北京珈程实例读取“官网价格与行程事实区”行动包的真实待补输入；
- 其他品牌可以得到不同数量、不同内容和不同优先级的主题；
- 用户可对任一主题选择“现在提供”“不适用”或“稍后增补”。

## 输出

- 一份不可变 `action-fact-intake.v1` 快照；
- 记录行动包、来源缺口数、个性化主题、稳定外壳、可接受回答状态和完整性门禁；
- 当前状态固定为等待事实；
- 未取得真实资料前，事实草案与发布权限均为关闭。

## 自动化边界

- AI 自动从诊断和行动包生成最少问题，不要求用户管理字段模板；
- 不根据行业惯例填价格、有效期、行程或服务标准；
- 不把北京珈程的字段复制给不相关品牌；
- 不调用 DeepSeek，不修改官网，不发布，不对外联系。

## 验收标准

1. 个性化主题直接来自已批准行动包，而不是前端或固定通用问卷；
2. 更换行动包后，主题数量和内容能随输入变化；
3. 每个主题都继承稳定证据外壳；
4. 支持“不适用”和“稍后增补”，不强迫品牌填写无关细节；
5. `factDraftAuthorized=false`、`publicationAuthorized=false`；
6. 真实数据库幂等、租户隔离、不可变和审计可验证。

## 非目标

- 不在本切片收集真实价格、行程或服务资料；
- 不生成官网页面蓝图、正文或结构化数据；
- 不替品牌决定业务重点；
- 不修改已通过的退款事实采集历史快照。

## Gate B-D 实施证据

- 稳定证据外壳：事实值/状态、适用范围、时效、依据、公开范围，共5项。
- 个性化生成：直接读取已批准行动包的 `humanInputs`；测试证明不同输入可生成3项或4项不同关注主题。
- 回答状态：现在提供、不适用、稍后增补，共3种；未填写不会被 AI 自动补全。
- 北京珈程真实实例：从“官网价格与行程事实区”行动包的21条来源缺口生成3个关注主题。
- 真实数据库：首次写入 `idempotent=false`，复跑 `idempotent=true`；`factDraftAuthorized=false`、`publicationAuthorized=false`。
- 自动验证：Node.js 24 下33个测试文件、140/140测试通过；PostgreSQL冷备恢复、Redis AOF恢复和Web生产构建通过。实现提交 `92d616ab89a1b3769ea7aa6c3640ed7a4eefe66a` 的 GitHub Linux CI `34935691374` 成功。
- 可视化验收：`http://127.0.0.1:4281/` 已接入真实验收数据库。独立自动浏览器通道连续连接失败，未将自动视觉检查标为通过。
- 未调用 DeepSeek，未收集真实价格/行程，未修改官网，未发布。
- 阿里云原生验证继续标记为 `blocked-by-host-policy`。

## Gate E 待验收

用户只需确认：稳定证据外壳是否足够统一，个性化主题是否应继续由每个品牌的诊断和行动包自动生成，以及“不适用/稍后增补”是否能避免无关业务细节拖慢使用。
