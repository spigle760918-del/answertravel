# AnswerTravel 产品需求文档（PRD）

版本：v0.1（上线前基线）  
产品定位：面向文旅目的地与旅游服务品牌，监控游客出发前向 AI 提出的目的地问题，并形成“监控 → 分析 → 内容优化 → 效果验证”的闭环。

## 1. 产品目标

AnswerTravel 解决三个问题：

1. 游客在 DeepSeek、豆包、Kimi、元宝等平台询问目的地问题时，品牌是否被推荐。
2. 哪些问题、平台和外部来源影响了品牌曝光与排名。
3. 如何基于真实回答生成可信内容，并验证发布后是否改善 AI 推荐表现。

### 1.1 MVP 成功指标

| 指标 | 目标 |
| --- | --- |
| 首次配置完成率 | 新用户在 10 分钟内完成团队、品牌、提问、竞品设置 |
| 数据采集成功率 | 每日任务成功率 ≥ 99% |
| 回答可追溯率 | 每条指标都能回溯到平台、问题、原始回答和来源 |
| 内容闭环 | 文章可完成生成、审核、发布、收录检查 |
| 权限正确率 | 无权用户无法读取或修改未授权品牌 |

## 2. 用户与权限

### 2.1 用户角色

| 角色 | 主要任务 | 权限范围 |
| --- | --- | --- |
| 团队管理员 | 管理工作空间、成员、品牌、渠道 | 全部团队与品牌 |
| 品牌管理员 | 管理指定品牌与业务配置 | 指定品牌的读写与发布 |
| 品牌编辑者 | 维护提问、素材和文章 | 指定品牌的内容读写 |
| 品牌成员 | 查看数据与回答记录 | 指定品牌只读 |

权限必须同时校验 `workspace_id`、`brand_id` 和角色，不能只依赖前端隐藏按钮。

## 3. 核心用户流程

### 3.1 首次使用

登录 → 创建工作空间 → 创建品牌 → 添加竞品 → 添加监控问题 → 选择平台与地区 → 启动首轮采集 → 查看概览。

### 3.2 日常监控

查看概览 → 按日期/平台/主题筛选 → 打开大模型回答 → 查看品牌提及与引用来源 → 识别未覆盖的问题。

### 3.3 内容优化

选择低曝光问题 → 选择文章结构与参考范文 → 生成草稿 → 事实与可信度审核 → SEO/GEO 检查 → 发布 → 收录检查 → 对比指标变化。

### 3.4 团队协作

管理员发送邀请 → 成员接受邀请 → 分配品牌范围与角色 → 成员执行内容或查看数据 → 审计日志记录关键操作。

## 4. 功能需求

### 4.1 认证与工作空间

- 支持邮箱登录、退出、会话续期和密码重置。
- 支持创建工作空间、修改名称/描述/头像。
- 支持生成邀请链接、接受邀请、撤销未接受邀请。
- 支持成员角色与品牌范围配置。
- 所有业务数据必须归属于工作空间，禁止跨租户访问。

验收：未登录访问业务 API 返回 401；未授权品牌返回 403 或空结果；成员被移除后原会话立即失效。

### 4.2 品牌与竞品

- 品牌字段：名称、别名、官网、语言、描述、备注、头像、地区。
- 竞品支持增删改查、排序和停用。
- 官网可作为来源匹配域名，支持多个域名和子域名规则。
- 品牌配置变更记录审计日志。

### 4.3 监控问题

- 支持按主题分组、批量创建、编辑、删除、暂停和恢复。
- 每条问题可指定平台、地区、语言和执行频率。
- 创建问题后生成采集任务，并为每个平台建立回答记录。
- 支持搜索、日期范围、主题、平台、提及状态和任务状态筛选。
- 支持问题去重和语义相似提醒，避免浪费监控额度。

### 4.4 大模型任务与回答记录

- 支持任务排队、运行、完成、失败、取消、重试。
- 保存请求参数、原始回答、模型版本、耗时、错误信息和重试次数。
- 提取品牌是否被提及、首次排名、曝光分数、情绪/风险标签。
- 允许查看完整回答、引用来源、评估时间、地区和语言。
- 同一问题可以按平台 Tab 对比回答。

### 4.5 概览与洞察

- 指标：品牌提及率、平均排名、曝光效果分数、监控问题数。
- 支持按日期、平台、主题、竞品和品牌筛选。
- 展示趋势、平台对比、主题排行和环比变化。
- 引用域名支持下钻：文章数、引用次数、品牌文章占比、引用趋势。
- 指标必须标注数据更新时间和样本量。

### 4.6 素材与可信度

- 支持文本、链接、图片、PDF、Word、Excel、CSV 素材。
- 素材状态：待审核、已通过、已拒绝、已过期。
- 记录来源、有效期、最后核验时间、引用次数和审核人。
- 价格、库存、签证、退改规则必须支持有效期字段。

### 4.7 文章生成、审核与发布

- 选择监控问题、文章类型、风格和参考范文。
- 生成草稿后可编辑标题、正文、摘要、关键词、slug 和引用。
- 事实审核项至少包括来源、更新时间、作者、联系方式、价格/规则。
- 文章状态：草稿、待审核、待发布、发布中、已发布、已收录、发布失败。
- 支持官网、WordPress、微信公众号等发布适配器。
- 发布任务必须幂等，失败可重试，收录检查可手动触发或定时执行。

## 5. 非功能需求

| 领域 | 要求 |
| --- | --- |
| 安全 | HTTPS、密码哈希、短期 access token、可撤销 refresh token、CORS 白名单、输入校验 |
| 隔离 | 所有查询带 workspace/brand 权限条件；后台任务不能越权读取 |
| 性能 | 列表接口 P95 < 500ms；概览查询支持预聚合；大模型任务异步执行 |
| 可靠性 | 任务可重试、接口幂等、数据库备份、错误可追踪 |
| 可观测性 | 结构化日志、任务指标、错误告警、审计日志 |
| 兼容性 | Chrome/Edge/Safari 最近两个大版本；移动端 375px 起适配 |
| 可访问性 | 键盘可操作、表单错误可读、颜色对比度满足 WCAG AA |
| 隐私 | 明确隐私政策、数据保留周期、用户删除与导出机制 |

## 6. MVP 不做范围

- 不在 MVP 内自研大模型，先接入已有平台或内部代理服务。
- 不在 MVP 内承诺真实搜索引擎排名提升，只展示可验证的曝光与引用变化。
- 不在 MVP 内做复杂计费、发票和企业采购流程。
- 不在 MVP 内支持无限品牌和无限模型，必须有套餐额度和配额提示。

## 7. 发布验收门槛

1. 生产数据库迁移可重复执行，备份恢复演练通过。
2. 登录、邀请、权限和租户隔离通过自动化测试。
3. 四类模型任务至少有一个真实适配器，其余平台有明确失败状态。
4. 文章发布、失败重试、重复点击和收录检查通过幂等测试。
5. 核心页面具备加载、空数据、错误、权限不足和移动端状态。
6. 具备 HTTPS、域名、日志、监控、告警和回滚方案。
