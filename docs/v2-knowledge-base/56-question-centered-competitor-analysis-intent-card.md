# 意图卡：以游客提问为单位的竞争对手分析 V1

状态：Gate A-F 已通过并封版

日期：2026-09-21

关联决策：`54-question-centered-analysis-evidence-intent-card.md`、`55-versioned-competitor-scope-intent-card.md`

## 1. 用户结果

用户从一个已批准的游客问题出发，查看品牌和范围内已确认实体在同一问题、平台、模型、区域、轮次和时间口径下的回答证据。

这个页面回答的是“这个游客问题的回答中，品牌与已确认实体各自出现了什么”，不是“谁是全市场第一”。

## 2. 页面内容

- 当前游客问题和问题组版本；
- 当前竞争范围版本、关系类型、区域和有效期；
- 每个实体的有效回答、失败样本、GEO 分析覆盖、确定提及和条件化排名；
- 品牌与实体的可比较状态，以及不可比较的具体原因；
- 可下钻的原始回答、主张、引用与页面快照。

## 3. 比较规则

只在以下条件同时成立时显示差异：

- 实体属于已批准竞争范围版本；
- 关系类型为 `direct_competitor` 或明确允许比较的 `alternative` ；
- 问题、平台、模型、采集方式、区域、时间窗口和轮次一致；
- 双方都有至少一条完成 GEO 分析的有效回答。

否则显示“不可比较”，不用 0 代替缺失证据，也不把失败当作品牌或竞品缺席。

## 4. 明确不做

- 不生成竞争力总分、市场份额或全市场排名；
- 不自动把 AI 回答里出现的名字加入竞争范围；
- 不发起新的竞品直问、费用采样或外部抓取；
- 不在没有可比证据时显示胜负结论；
- 不把竞品分析变成通用市场情报或 CRM。

## 5. 验收条件

1. 每个竞对数字都可回到具体游客问题、原始回答与 GEO 分析运行。
2. 无范围、无共同口径或样本不足时，显示诚实空状态。
3. 多租户不串用竞争范围、实体和回答。
4. 桌面使用表格，手机使用逐问题卡片，均可看到可比性与证据限制。
5. 用户 Gate E 确认前，不进入生产候选。

## 6. 当前实现证据

- 已新增 `/api/v1/competitor-analysis` 只读接口，租户由服务端会话解析，不接受浏览器租户覆盖。
- 已新增 `/analysis/competitors` 页面，桌面使用问题级表格，移动端使用逐问题卡片。
- 契约明确不包含市场份额、竞争力总分或全市场排名字段。
- Node.js 24 类型检查、Web 构建和产品读取契约测试通过；完整测试结果为 41 个测试文件、181 项测试，131 项通过、50 项跳过。
- 用户已确认本地预览中的页面文案、状态和布局；本切片 Gate A-F 封版。未部署生产、未调用模型、未创建竞品采样任务。
