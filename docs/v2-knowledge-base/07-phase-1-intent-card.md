# Phase 1 意图卡：工程与证据骨架

状态：已确认并实施中  
确认依据：用户于 2026-09-13 回复“以你确定的 V2 为准。继续”  
版本：1.0

## 用户价值

Phase 1 不追求可销售页面，而是建立以后不会再次推翻的地基。完成后，V2 新增的每条回答、指标、AI 判断和动作都必须有固定身份、版本、租户、证据来源和审计记录。

## 本阶段交付

1. 与 V1 隔离的 `v2/` 工程；
2. TypeScript 模块化单体骨架；
3. Node.js LTS、配置和依赖锁定；
4. PostgreSQL 初始迁移与迁移校验；
5. 不可变证据信封、事实等级和审计事件契约；
6. 持久任务契约，以及调度器与 Worker 的边界；
7. 健康检查和基础可观察性；
8. 单元、契约、架构和迁移测试入口；
9. CI、开发启动说明和环境样例；
10. Phase 1 实施证据与遗留风险报告。

## 本阶段明确不做

- 不接真实 AI Provider；
- 不开发品牌提及率看板；
- 不生成文章或发布；
- 不迁移 V1 业务数据；
- 不使用 V1 模拟趋势、竞品和收录逻辑；
- 不复制 GEOFlow 或其他仓库代码；
- 不加入为了“看起来完整”的演示页面。

## 核心输入

- 已确认产品章程、总体架构和指标原则；
- 当前运行环境；
- V1 中可作为风险参考的真实经验；
- 外部项目的方法与边界台账。

## 核心输出

- 可运行的最小 API/Worker 工程；
- 可验证的 PostgreSQL Schema；
- 证据和审计契约；
- 自动化测试结果；
- 未满足生产要求的明确列表。

## 失败与停止条件

- 无法在受支持的 Node.js LTS 运行；
- 开发/测试环境只能依赖 SQLite；
- 原始证据能够被普通更新覆盖；
- 模块之间可以绕过契约直接写入他人数据；
- 测试使用的 fixture 可能进入生产查询；
- 需要绕过平台授权或安全控制才能继续。

## 验收标准

- `v2/` 与 V1 文件和运行数据隔离；
- 一条示例证据可以从写入、读取到审计完整追溯；
- 修改不可变证据的测试明确失败；
- 租户不匹配的读取明确失败；
- 重复任务不会造成重复事实；
- 健康检查能区分进程健康、数据库健康和队列健康；
- 所有测试数据只存在于测试环境；
- 一条命令可以运行检查与测试；
- 知识库记录已完成证据和未完成风险。
