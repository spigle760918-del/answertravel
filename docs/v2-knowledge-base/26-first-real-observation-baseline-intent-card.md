# 意图卡：北京珈程首次真实观察基线与自动诊断 V1

状态：Gate E 待用户验收
日期：2026-09-14

## 为什么现在做

北京珈程的公开品牌真相和首批 20 条真实游客问题已经验收。下一步应使用固定问题快照建立第一轮真实 DeepSeek API 观察基线，让品牌负责人看到 AI 实际如何回答、是否提及品牌、怎样描述品牌以及是否出现可追溯的来源线索，而不是继续停留在问题草案。

## 推荐采样计划

- 问题：严格使用 `25-real-question-panel-intent-card.md` 中已验收的 20 条，不重新生成或改写；
- 轮次：每题 2 轮，共 40 个计划样本；
- Provider/终端：仅 DeepSeek API，模型请求名 `deepseek-chat`，实际返回模型名按原始响应保存；
- 上下文：中文，区域上下文标记为“中国大陆游客计划北京旅行”，该标记不代表 Provider 真实定位；
- 参数：低随机度、单回答最大 1000 tokens、60 秒超时、最多 3 次尝试；
- 总预算：本切片硬上限 60,000 tokens，达到上限立即停止剩余任务，不自动追加预算；
- 问题分组：中性品类与品牌直问分别统计，品牌直问不进入自然提及率分母；
- 竞品：仅用于中性回答中的自然实体识别，不生成或采集竞品直问。

Gate A 的 Yes 同时代表对上述最多 40 个 DeepSeek API 计划样本和 60,000 tokens 硬上限的明确授权。没有 Yes 不调用真实答案 API。

## 输入

- 已批准的北京珈程品牌真相版本；
- 已验收且不可变的 20 条问题快照；
- 已确认的三家竞品监控实体；
- DeepSeek Key，仅通过进程环境安全注入，不写入数据库、日志、知识库或 Git；
- 已封版的观察队列、不可变证据、引用扫描、GEO 情报和差距诊断契约。

## 输出

1. 已批准且不可覆盖的北京珈程问题组版本；
2. 40 个“问题×轮次”持久化计划任务及明确状态；
3. 每次尝试、失败和成功回答的不可变原始证据、哈希、模型、时间、用量和结束原因；
4. 回答正文中的引用候选与来源状态；没有引用时明确显示 0，不伪造信源；
5. 中性问题的品牌与竞品自然提及，品牌直问下 AI 对珈程的主张、情感和事实冲突；
6. 条件化排名：只有回答存在明确有序推荐时适用，否则为“不适用”；
7. 第一轮证据充分度和差距诊断；样本不足时返回“证据不足”，不强行给内容方向；
8. 面向业务负责人的网页验收，可逐条下钻到真实回答和采集上下文。

## 自动停止与失败边界

- Token 达到 60,000、密钥失效、余额/限额异常或连续 Provider 故障时停止；
- 截断、空正文、超时、协议错误和最终失败保留证据，不计入有效回答；
- 重试不得覆盖失败尝试，同一幂等键不得产生两个有效成功样本；
- 若有效样本不足以支持比较，系统只报告缺口并建议补采，不制造品牌或竞品胜负；
- DeepSeek API 结果不得表述为 DeepSeek Web/App、联网搜索或其他 AI 模型表现。

## 人与 AI 的分工

- 人只需在 Gate A 对采样范围和硬预算回答 Yes/No；
- AI 自动冻结批准问题组、创建计划、入队、重试、保存证据、扫描引用、计算基础指标、诊断并更新验收页面；
- 只有密钥失效、预算扩张、竞品直问或对外发布等真实门禁才再次请求人工确认。

## 非目标

- 不接入 DeepSeek Web/App、豆包、千问、Kimi、元宝或其他模型；
- 不采集“某竞品怎么样”或品牌对比问题；
- 不据一次基线宣称长期趋势、统计显著或因果关系；
- 不生成优化文章、不发布内容、不修改官网或第三方账号；
- 不自动扩大到每日调度，周期化监控在首次基线验收后另立意图卡。
