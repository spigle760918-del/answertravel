# Phase 1 验证契约 v1

日期：2026-09-13。属于已确认 Phase 1 内部实现，不增加产品范围。

## 环境与边界

- 本地采用独立 PostgreSQL 16.14 与 Redis 7.2.16 测试进程，仅监听回环地址、使用随机端口与独立临时数据目录；不安装系统服务，不访问 V1 数据。
- PostgreSQL 通过固定版本的 `embedded-postgres` 开发依赖获取；Redis Windows 社区移植版仅用于本地验证，压缩包按发布页 SHA-256 校验；生产及 CI 使用 Linux。
- 初始化/迁移账号与应用账号分离；应用账号必须无超级用户和 BYPASSRLS 权限。测试库名称必须以 `_test` 结尾。
- 测试产物均为明确标记的 fixture，测试结束后关闭本次创建的进程；保留失败日志及恢复证据，不触碰其他进程或数据库。

## 本切片验收

1. 正常：追加证据与审计原子提交，读取返回同一哈希和采集上下文。
2. 边界：重复/并发投递同一证据只产生一条证据和一条追加审计；跨租户读不到，跨租户写入被拒绝；事务结束不残留租户上下文。
3. 失败：证据/审计更新、删除及截断失败；审计失败时证据事务回滚；高权限应用账号拒绝服务。
4. 迁移：首次执行与重复执行通过，已应用文件篡改被拒绝，失败迁移的 DDL 和登记均回滚。
5. 队列：按租户和幂等键生成稳定任务 ID，任务进入 Redis；Worker 产生可追溯的基础探针证据；重试/重复投递不重复事实；不支持的契约版本明确失败。
6. 恢复：重启独立 Redis 后等待任务仍存在；PostgreSQL 备份恢复到新的测试库后证据与审计可读取。
7. 健康：存活检查、真实依赖就绪、依赖不可用三种状态均有测试。

## 完成口径

所有检查记录真实运行结果；缺少测试服务时，完整验收命令必须失败，不得以跳过冒充通过。本地 Windows 验证与 Linux CI 验证分别记录。没有真实 AI 调用、业务指标、内容生成或发布。
