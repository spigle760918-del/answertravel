# AnswerTravel 品牌优化诊断方法

## 目标

“优化品牌输出”必须从游客问题的真实采集结果开始，形成：

`监控问题 → 大模型回答 → 品牌/竞品诊断 → 内容任务书 → 生成与审核 → 再次采集验证`

不得仅按通用文章模板生成内容，也不得把演示数据、推测或未抓取正文的信源包装成真实洞察。

## 样本口径

- 分析单位：当前品牌下状态为 `completed` 且具有回答正文的采集记录。
- 真实采集优先：只要存在 `collectionMode=live` 的回答，正式诊断只使用真实回答。
- 模拟数据：保留在回答记录中供产品演示，但不进入正式诊断，并显示排除数量。
- 品牌匹配：品牌名称和品牌别名任一出现在回答正文，即计为一次提及。
- 竞品匹配：竞品名称出现在同一批回答正文，即计为该竞品一次提及。

## 自身品牌指标

### 提及率

`品牌提及率 = 出现品牌或别名的回答数 ÷ 有效采集回答数 × 100%`

页面必须同时展示百分比和原始分子/分母，不得只展示综合分。

### 排名

- 只统计已提及品牌的回答。
- 优先使用采集评估保存的首次排名。
- 没有结构化排名时，按品牌与竞品在回答中首次出现的先后顺序估算。

### AI 情感标签

当前采用可解释规则标签：

- 值得推荐：命中“值得推荐、首选、可靠、靠谱、专业、放心”等正向表达。
- 一般/中性：品牌被提及，但正负向证据相当或没有明确态度。
- 不建议/谨慎：命中“不建议、不推荐、谨慎、投诉、风险、争议”等负向表达占优。

标签必须返回命中的证据词。该结果属于启发式诊断，不等同于人工舆情结论。

## 信源诊断

- 网址数量：去重后的可访问引用 URL 数量。
- 域名数量：去重后的引用域名数量。
- 内容频次：同一 URL 在回答中被引用的累计次数。
- 内容模态：根据 URL、文件类型和标题标注图文、视频、图片/图集、社交内容、音频或报告。
- AI 偏好结构：识别结论先行、分层标题、清单/步骤、量化信息、对比框架、评价依据与 FAQ。

如果只有 URL/标题而没有信源正文，“AI 偏好结构”必须标为“待抓取信源正文”。

## 担当与服务颗粒度

### 担当/承诺信号

识别服务保障、退改、赔付、响应时限、24 小时服务、专人负责等可承担责任的表达。生成内容时必须补充适用条件、责任主体和边界，禁止生成无法兑现的绝对承诺。

### 服务颗粒度

识别接送、接驳、导游、领队、住宿、用车、保险、餐食、门票、签证、客服、应急、老人/儿童/无障碍服务等可独立比较的服务单元。

## 竞品比较

自身与竞品采用同一套样本和指标，比较：

1. 提及率与平均排名。
2. 回答平台覆盖数量。
3. 引用网址、域名及引用频次。
4. 内容模态丰富度。
5. 官方、媒体、游客、达人、专家、第三方机构等测评角色数量。
6. 可验证承诺强度。
7. 产品与服务颗粒度。
8. 是否采用便于 AI 摘取的内容结构。

没有证据时显示“当前样本未发现”，不得自动断言自身或竞品更好。

## 内容生成约束

每次生成文章必须保存不可变的分析快照、内容任务书和来源回答 ID。任务书至少包含：

- 优化目标及目标监控问题。
- 当前品牌缺口与竞品领先项。
- 必须补齐的公开来源、适用边界、响应时限、退改/赔付、第三方评价等证据。
- 推荐结构：结论先行、适用人群、评价维度、量化对比、服务明细、承诺边界、证据链接、FAQ。
- 禁止项：无法核验的“第一、唯一、最好”，无条件绝对承诺，伪造引用/评价/数据。

## 当前能力边界

- DeepSeek Chat API 已能返回并保存真实回答，但当前实例的真实回答没有结构化引用链接。
- 系统已能分析回答正文与引用元信息。
- 信源正文抓取、页面模态识别、正文结构评分和引用内容级去重尚待后续采集服务完成。
- 当前仅有一个真实回答样本时，指标可计算但不具备统计稳定性，页面必须显示真实样本数。
